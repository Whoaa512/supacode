## 2. Design

One picker, the existing browse mode with purpose `.newSession`, gains two things: a list of known
directories (local and remote) and an agent/shell choice. Confirm mints a task through the existing
launch path; the only new launch behaviour is "first tab has no input" for a shell.

### 2.1 New types — new file `supacode/Domain/NewTaskPicker.swift`

```swift
/// What a picked task starts with (D3).
nonisolated enum NewTaskKind: Equatable, Sendable { case agent, shell }

/// A roster directory the picker can start a task on. A snapshot taken when the picker opens:
/// only `id` is trusted at confirm time.
nonisolated struct NewTaskDirectory: Equatable, Identifiable, Sendable {
  let id: Worktree.ID
  let name: String          // worktree.name
  let repositoryName: String?  // repositories.repositoryName(for:), nil for a folder
  let path: String          // remote: the remote path; local: tilde-abbreviated path
  let localPath: String?    // absolute local path; nil for remote
  let hostLabel: String?    // host.displayAuthority; nil for local
  var searchText: String { [repositoryName, name, hostLabel, path].compactMap { $0 }.joined(separator: " ") }
}
```

### 2.2 `CommandPaletteFeature`

`BrowseState` additions:
```swift
var known: [NewTaskDirectory] = []          // set once by enterBrowseMode
var knownMatches: [NewTaskDirectory] = []   // what the list renders in known mode
var kind: NewTaskKind = .agent
/// Known mode: the roster list, not the filesystem. Slash-less text is a fuzzy query over
/// `known`; a `/` anywhere, or bare `~`, is a path and uses the existing browser untouched.
var listsKnown: Bool {
  guard purpose == .newSession, !known.isEmpty else { return false }
  let text = pathQuery.trimmingCharacters(in: .whitespaces)
  return !text.contains("/") && text != "~"
}
var rowCount: Int { listsKnown ? knownMatches.count : filteredEntries.count }
var selectedKnown: NewTaskDirectory? {
  guard listsKnown, let selectedIndex, knownMatches.indices.contains(selectedIndex) else { return nil }
  return knownMatches[selectedIndex]
}
```
Invariant kept by the reducer: in known mode `filteredEntries == []` (so `selectedEntry` is nil
without changing it); in path mode `knownMatches == []`. `selectedIndex` indexes the active list.

Actions:
- `enterBrowseMode(basePath: URL?, purpose: BrowsePurpose = .openRepository, known: [NewTaskDirectory] = [])`.
  Sets `browse.known = known` (only for `.newSession`). Initial query: `""` when
  `purpose == .newSession && !known.isEmpty`, otherwise exactly as today (so with an empty roster
  the picker still opens on `basePath`).
- `browsePathQueryChanged`: first statement after `setPathQuery`:
  ```swift
  if state.browse.listsKnown {
    state.browse.isLoading = false
    state.browse.entries = []; state.browse.searchResults = []; state.browse.loadedDirectory = nil
    Self.refreshBrowseRows(&state.browse)
    return .merge(.cancel(id: CancelID.browseLoad), .cancel(id: CancelID.browseSearch))
  }
  ```
  No filesystem client call in known mode.
- `refreshBrowseRows`: when `listsKnown`, set `filteredEntries = []` and
  `knownMatches = query.isEmpty ? known : BrowseFuzzyMatch.ranked(known, query: query, path: \.searchText)`,
  both capped at `browseRowLimit`, order of `known` preserved for ties (`ranked` already does);
  keep the selection by `id` if it survives, else index 0, else nil. Otherwise set
  `knownMatches = []` and run the existing body.
- `browseDirectoryLoaded`, `browseSearchResultsLoaded`: add `guard !state.browse.listsKnown` (a load
  cancelled late must not fill a list the picker is not showing).
- `browseMoveSelection`: use `state.browse.rowCount`.
- `browseSubmit`, `browseForceOpen`: in known mode, `guard let known = state.browse.selectedKnown
  else { return .none }` then `.send(.browseSelectKnown(known.id))`. Path mode unchanged.
- `browseAutocomplete` (Tab): in known mode, a selected row with `localPath` sends
  `.browsePathQueryChanged(BrowsePath.descending(into: localPath, from: "~/"))` (browse from that
  directory); a remote row is a no-op. Path mode unchanged.
- `browseNavigateUp`: no-op in known mode.
- new `browseSelectKnown(Worktree.ID)` (also the row's click): `guard purpose == .newSession`;
  read `kind`; `isPresented = false`; `resetForDismiss()`;
  `.send(.delegate(.newTaskDirectoryPicked(id, kind: kind)))`.
- new `browseToggleKind`: `guard purpose == .newSession`; flip `browse.kind`. Nothing else changes
  (query, selection, rows stay).
- new `browseKindChanged(NewTaskKind)` for the segmented control (sets `browse.kind`, same guard).
- `browseSelectRepository(url)`, `.newSession` branch: read `kind` **before** `resetForDismiss()`
  and send `.delegate(.newSessionDirectorySelected(url, kind: kind))`.
- `browseOpenNativePanel`: read `kind` before the reset; send
  `.delegate(.browseOpenNativePanel(purpose, kind: kind))`.

`Delegate`:
- `newSessionDirectorySelected(URL, kind: NewTaskKind = .agent)`
- `browseOpenNativePanel(BrowsePurpose, kind: NewTaskKind = .agent)`
- new `newTaskDirectoryPicked(Worktree.ID, kind: NewTaskKind)`

The defaults keep existing constructions and key-path receives compiling; pattern matches that

- `handleNewTask(inDirectory:kind:state:)` → `launchNewSession(in:kind:state:)`. Add to its guard,
  on current state: the worktree is in the roster, `!isMissing`,
  `!state.repositories.isWorktreeArchived(id)`, and
  `state.repositories.sidebarItems[id: id]?.lifecycle.isTerminating != true`. Otherwise `.none`
  (log a warning), nothing minted.
- `launchSessionTab`: only the command changes.

  let create: TerminalClient.Command =
    switch pending.kind {
    case .agent: .createTabWithInput(layoutID, directory, input: pending.command,
                   runSetupScriptIfNew: false, title: nil, focusing: true, anchor: nil)
    case .shell: .createTab(layoutID, directory, runSetupScriptIfNew: false, focusing: true)

- new `static func newTaskDirectories(state: State) -> [NewTaskDirectory]`:
  ```
  rows = state.repositories.orderedSidebarItems()
           .filter { $0.lifecycle == .idle }               // not pending, not terminating
           .compactMap { state.repositories.worktree(for: $0.id) }
           .filter { !$0.isMissing }                        // archived rows are not in the sidebar order

        then 1 + index in repositories.worktreeMRU, then sidebar order (stable sort)
  map to NewTaskDirectory (repositoryName nil when worktree.isFolder)
  ```
  So the first row, preselected, is the directory of the task on screen: ⌘⌥⇧N then ↵ equals Cmd-N,
  and also works when that task is remote (closes the "P:" note under T7 r2).

## 3. Destructive and persistence paths

P1 adds no close, kill, prune, settle or file-format path, and no timer.
- Minting writes nothing itself. The record appears through the existing writer when the first tab
  exists; a launch whose tab never appears leaves no record, no member, no selection (existing
  `PendingTaskLaunch` rule). Do not add a "create the record first" step.
- A shell-only task is deleted only by the existing rule (last tab closed, no session listed,
  decided in `handleLayoutChanged` on the current layout and members). P1 must not add a second
  deletion path and must not delete or settle anything on picker dismiss, cancel or failure.
- Never select the minted task before its tab exists. For a shell this is a correctness rule, not
  cosmetics: an early `selectTask` runs `ensureInitialTab`, and the task would get two tabs.
- Confirm decides on current state by id: `newTask(inDirectory:kind:)` looks the worktree up in the
  roster at confirm time. The `NewTaskDirectory` snapshot's name/path/host are display only and are
  never used to build a `DirectoryContext`.
- Order: `known` keeps the order `newTaskDirectories` built; `knownMatches` for an empty query is
  `known` exactly; `pendingTaskLaunches` stays append-ordered with only the last `isShown`.
  `TaskRecord.sessions` is not touched (a shell launch lists no member). Nothing here hydrates.
- `runSetupScriptIfNew: false` for both kinds, as every session launch today (A14 is the
  directory's own-task business).

## 4. Edge cases and races

| Case | Required behaviour |
|---|---|
| Picked directory removed, archived, gone missing or terminating between open and confirm | Nothing sent, nothing minted, `pendingSessionLaunch` stays nil. |
| Confirm while `pendingSessionLaunch != nil` (another launch or a resume probe) | Dropped, as Cmd-N today. No queueing. |
| Two picker launches before either tab appears | Two tasks, two `PendingTaskLaunch` entries; only the later is selected, whichever tab arrives first (existing T7 r2 rule; add the shell variant test). |
| Shell tab creation fails | No task, no row, no selection; the pending entry stays inert for the run (existing decision). |
| Shell on an unregistered local folder | `registerSessionFolder`, then one `createTab` on `repositoriesChanged`; kind survives in `pendingSessionLaunch`. |
| Path picked that is already a roster directory | `worktreeForCwd` hit, immediate launch on that directory (no duplicate folder). |
| Path not a readable directory | Existing guard: warning, nothing minted. |
| Remote known directory | Launch goes to the host via `DirectoryContext(worktree:)`; `FileManager` is never asked; Tab-to-browse is a no-op on that row. |
| Remote task on screen, picker opened | Its directory is the first known row; `basePath` is still the local fallback and only used if `known` is empty. |
| Empty roster | Picker opens in path mode on `basePath`, as today; the kind toggle still works. |
| Stale directory load or search arriving in known mode | Ignored; `knownMatches` and selection unchanged. |
| Kind toggled, then query edited or mode switched known↔path | Kind persists until dismiss; `resetForDismiss` returns it to `.agent`. |
| Native panel chosen with Shell, then cancelled | Purpose (and kind) reset by `openPanelCompleted(nil)`; next open panel is unaffected. |
| `.openRepository` purpose | Byte-for-byte unchanged: `listsKnown` false, toggle actions are no-ops, delegates as before. |
| Agent later started in the picker's shell task | Existing membership (T7) makes it primary; title switch is S3. No P1 code. |
| Last tab of the shell task closed | Task removed by the existing rule; selection falls to the directory's resolver target. |
| Slash-less text in `.newSession` | Now filters known directories, no longer the home listing. Intended; `~/x` still browses. |

- Typing `~/` or `/` switches to the filesystem list and back without flicker; ⇥ on a known row
  jumps into browsing it.
- A shell task appears as a row titled by its directory, selected and focused, with exactly one
  tab; closing that tab removes the row.
- A remote directory starts on its host (agent and shell), with the host unreachable case showing
  the terminal's own error and no stuck row.
- Native "Choose Folder…" honours the chosen kind.
- Tooltips name action and key (A35).

## 8. Decisions and contradictions

Decisions the plan left open:
1. **Known directories are a mode of the same list, chosen by query shape** (slash-less = roster,
   path text = filesystem). One field, one selection index, no tabs or second palette mode; the
   existing browser code runs untouched for paths. Cost: in this picker a slash-less word no longer
   filters the home listing.
2. **The choice is a toggle in picker state (`BrowseState.kind`), default Agent, ⇧⇥**, not a
   modifier on ↵: it is visible, works with the mouse and the native panel, and is one reducer
   field to test. Not remembered across opens.
3. **The kind travels in the payload** of every hop (`Delegate`, `OpenPanelPurpose`, `Action`,
   `PendingSessionLaunch`). No "pending kind" field in `AppFeature.State` that a cancelled panel
   could leave behind.
4. **Shell minting reuses the session launch path** with `.createTab` instead of
   `.createTabWithInput`. Same task-per-launch id, same select-when-tab-exists rule, same failure
   behaviour; no new terminal command.
5. **Known list = idle, non-missing, non-archived roster rows; current task's directory first, then
   MRU, then sidebar order.** Orphan-task directories are not offered (no roster entry to build a
   `DirectoryContext` from; reach them by path if local).
6. **Remote = picking a remote roster directory only.** The picker cannot browse a remote
   filesystem or name an unregistered remote path (D3: "remote is covered by picking a remote
   directory").
7. **Confirm-time guard extended** (`handleNewTask`): archived and terminating directories mint
   nothing. This also tightens the existing "New task here" button, which was reachable only for a
   selected live worktree anyway.
8. **No setup script** for a picker-minted task, same as every session launch.

Contradictions with the plan or the agreed decisions:
- **Chords.** D3 and the plan say "Cmd-N" and "Cmd-Shift-N". In source, ⌘N is
  `AppShortcuts.newWorktree`, ⌘⇧N is `newSession` (the plan's "Cmd-N"), and the picker is
  `newSessionInDirectory` on ⌘⌥⇧N (`SessionShortcutTests` pins all three, including the Ghostty
  unbind lines). This brief does **not** rebind: it would take ⌘N from New Worktree and touch user
  overrides, which D3 never discusses. If cj wants D3's literal chords, it is a separate
  three-default change in `AppShortcuts` plus `SessionShortcutTests`; ask before doing it.
- **Plan's test list** names three cases (local agent, local shell, remote directory); this brief
  adds remote shell and the unregistered-folder shell, since both reach different code.
- **Plan's file list** names `CommandPaletteFeature.swift` "view for the picker": no new view file;
  `CommandPaletteBrowseView` is extended. `RepositoriesFeature` (`OpenPanelPurpose`) is touched
  though the plan does not list it.
- **Open question 15** (default agent `pi`) is kept hardcoded; the picker offers no agent choice
  beyond agent-or-shell (D3).
