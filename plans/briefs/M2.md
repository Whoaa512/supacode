## 1. What exists today

- **Contents are global, hosts are not.** `ContentRuntime` (`contents: [ContentID: any TabContent]`, `pendingKill`) is one registry for all layouts. A tab is a value (`TabItem` in `Pane.tabs` in `LayoutFeature.State.layout`). So "moving a runtime" moves nothing in `ContentRuntime`; what is per-task is:
  - `WorktreeTerminalManager.hosts: [LayoutID: WorktreeContentHost]` and each host's per-surface/per-tab bookkeeping: `notifications`, `surfaceStates` (observed class instances), `lastCustomNotificationAt`, `pendingAgentOSCNotifications`, `pendingExplicitSurfaceCloseIDs`, `pendingUserCloseSurfaceIDs`, `automaticCloseSurfaceIDs`, `bypassCloseConfirmationSurfaceIDs`, `lastSweptContentIDs`, `lastDormantContentIDs`, `lastTabProgressDisplays`, `blockingScripts`, `completedBlockingScriptTabs`, `blockingScriptLaunchDirectories`, `lastBlockingScriptTabByKind`, `lastEmittedFocusSurfaceId`, `dormantSessionWatchers`.
  - the live `GhosttySurfaceView` callbacks, set once by `LayoutSurfaceConduit.wire` and capturing **the host object**.
  - the `ContentRequest` a `TerminalContent` was built with: `TerminalContentBuilder.terminalContent` captures `request.worktreeID` (the creating layout) in `makeSurface` (directory lookup, `SUPACODE_TASK_ID`, `wireSurface`, `environmentExtras`), and `supacodeApp.makeContentFactory`'s `wireSurface` closure captures it for `handleUnexpectedZmxClose(_:worktreeID:)`.
- **The only kill paths**: `LayoutFeature.reap` (via `reduceCloseTab`: `contentRuntime.remove(_, tombstone: true)` + `ContentSessionKiller.kill` → `WorktreeTerminalManager.killSession`), `WorktreeTerminalManager.removeLayout`, `prune`, `pruneBareSurfacesOnRestore`, `terminateAllSessions`, `reapOrphanSessions` (anything not in `TaskLayoutsFile.allKnownSurfaceIDs`).
- **The close signal**: `WorktreeContentHost.reconcileContentLifecycle` diffs `layout()` against `lastSweptContentIDs`; a content that left calls `cleanupSurfaceState` → `onUserClosedSurfaces` / `onSurfacesClosed` → manager emits `.userClosedSurfaces` / `.surfacesClosed` (+ `ScrollbackPersistence.removeFiles`) → `AppFeature` settles sessions / `agentPresence(.surfacesClosed)` drops records. It also calls `handleBlockingScriptTabClosed` (reports the script cancelled) for a tracked tab that left. It runs from `handleLayoutChanged(for:)`, which `TerminalsFeature` fires through `LayoutChangeObserver.layoutChanged` for every `.layouts(.element)` action. **A tab leaving a layout looks exactly like a close.** This is the slice's main risk.
- `handleLayoutChanged` ends with `removeTaskIfEmptied` (gated on `heldContentAtLastSweep`).
- **Settle triggers** in `AppFeature+Sessions.swift`: `taskClosedForSettle` (only `closeAllTabsRequested` / `confirmCloseAll`), `.terminalEvent(.userClosedSurfaces)`, `settleReplacedOrEndedSession`. `sessionsLinkReducer` runs on every `.terminals` action and calls `membershipEffect` → `TaskMembership.reconciled`, which appends a reporting agent to **the task that holds its surface** (`surfaceIndex`), in surface-uuid order, and never removes a session.
- **Membership** `TerminalsFeature.State.members: [LayoutID: [TaskMember]]` (primary first), `storedSessions` (`.pending/.loaded/.unreadable`), `pendingMembership`, `removedLayoutIDs`; `.detachLayout` clears a layout's `layouts/directories/members/activeTasks/recentLayoutIDs/selectionOrder` entries and inserts into `removedLayoutIDs`. `.layoutsHydrated` and `loadStoredSessions`/`hydratedMembers` merge stored lists into the run's ("a later read only adds"), without consulting `removedLayoutIDs`.
- **Hibernation** lives in `TerminalsFeature`: `hibernationArmedTabs`, `hibernationDeferralLogged`, `wakeRequestedTabs` are keyed by `TabID` only; `armGraceTimer(worktreeID:tabID:)` bakes the layout id into `.hibernationGraceElapsed`, cancel id `HibernationTimerID.tab`. `reconcileHibernation` re-derives everything from `layouts`.
- **Pane windows**: `PaneWindowManager.controllers` keyed `(LayoutID, PaneID)`; `reconcile(worktreeID:)` and `closeAll(for:)` tear down controllers; `PaneWindowController.tearDown` closes the window only, never a tab.
- **Persistence**: `LayoutsIncrementalWriter.flush(records: [LayoutID: RecordChange])` applies the whole dictionary in **one** read-modify-write. `.record` never drops a stored session (`TaskMembership.storing`); `.delete` removes the record, its `activeTasks` entries, and the directory's `origins` entry when it was the directory's last task. Manager side: `markLayoutDirty` (1 s debounce) → `flushLayoutSnapshot`; `deleteLayoutSnapshot` awaits `layoutFlushTasks[id]` then deletes; `recordChange(for:layout:)` builds a `.record` from `hosts[id]` + `terminals.members`; quit path `saveAllLayoutSnapshots` writes **hosted layouts only** via `flushSync`.
- **Command addressing**: `TerminalsFeature.State.commandLayoutID(forDirectory:task:holding:shown:)`; a named task not in `directories` on that directory returns nil. T11 Progress left to M2: a merged-away `SUPACODE_TASK_ID`.
- Remote: `killSession` picks the remote host from `hosts[layoutID]?.context.host`; after a relaunch `LayoutFeature.reduceWakeTab` rebuilds a content with `worktreeID: state.id`, i.e. the **owning** task's directory and host.

## 2. Design

### M2a — a content's owner is looked up, never remembered

1. `TerminalsFeature.State`:
   `func layoutID(holdingContent id: ContentID) -> LayoutID?` — first layout whose `layout.tab(containingContent:)` is non-nil. Linear scan; called only at spawn, wake and unexpected close.
2. `WorktreeTerminalManager`:
   - `func owningLayoutID(of contentID: ContentID) -> LayoutID?` → `appStore?.withState { $0.terminals.layoutID(holdingContent: contentID) }`.
   - `func wireSurface(_ view: GhosttySurfaceView, contentID: ContentID, layoutID: LayoutID)`: body of today's `wireSurface` closure in `supacodeApp.makeContentFactory` (resolve `worktree(forLayout:)`, `host(for:context:)`, build `LayoutSurfaceConduit`, `.wire`). Use `hosts[layoutID]` when it exists before falling back to the worktree lookup. The `handleUnexpectedZmxClose` closure passes `layoutID`.
   - `handleUnexpectedZmxClose(_:worktreeID:)`: after `await listSessionsWithClients()`, replace the id with `owningLayoutID(of: ContentID(rawValue: surfaceID)) ?? worktreeID` before every `hosts[...]` / `sendLayout` use.
3. `TerminalContentBuilder`: new field `var owner: (ContentID) -> LayoutID?` (no default, like `wireSurface`). In `makeSurface`: `effective.worktreeID = owner(request.contentID) ?? request.worktreeID` as the first statement after `var effective = request`; use `effective.worktreeID` for `lookUpDirectory(...) ?? capturedDirectory`. `plan(for: effective…)`, `wireSurface(view, effective)`, `environmentExtras(effective)` then follow the current owner. `supacodeApp`: `owner: { terminalManager?.owningLayoutID(of: $0) }`, `wireSurface: { view, request in terminalManager?.wireSurface(view, contentID: request.contentID, layoutID: request.worktreeID) }`.
   At first creation the tab is not in any layout yet (`provisionContent` runs before the insert) so `owner` is nil and the request's id stands: behaviour unchanged.

### M2b — the transfer

**Types** (`TerminalClient.swift`):
```swift
nonisolated enum TabTransferScope: Equatable, Sendable {
  case all                                   // merge: every tab and every member
  case tab(TabID, members: [TaskMember])     // detach: one tab and the members M3 says ride on it
}
nonisolated enum TabTransferRefusal: String, Equatable, Sendable {
  case sameTask, notReady, unknownSource, unknownDestination, destinationExists,
       unknownTab, memberNotInSource, confirmationPending, differentMachine, scriptRunning, quitting
}
// Command
case transferTabs(from: LayoutID, to: LayoutID, DirectoryContext /* destination */, scope: TabTransferScope)
// Events
case tabsTransferred(from: LayoutID, to: LayoutID, tabIDs: [TabID], sourceRemoved: Bool)
case tabsTransferFailed(from: LayoutID, to: LayoutID, reason: TabTransferRefusal)
```
Add the cases to every exhaustive switch the compiler names (`handleManagementCommand`'s assertion list, `WorktreeMenuSnapshot`, `label(for:)`). `handleTabCommand` handles `.transferTabs`. `AppFeature` handles both events with `return .none` until M3.

**`TerminalsFeature`**
- State: `var layoutsLoaded = false`, set true in `.layoutsHydrated` (existing exhaustive tests of that action gain `$0.layoutsLoaded = true`).
- `func transferRefusal(from:to:scope:destination: TaskRecord.Directory) -> TabTransferRefusal?` on `State`, pure, checked in this order:
  `from == to` → `.sameTask`; `!layoutsLoaded || storedSessions != .loaded || layoutsAreReadOnly` → `.notReady`; `layouts[id: from] == nil` → `.unknownSource`; scope `.all` and `layouts[id: to] == nil` → `.unknownDestination`; scope `.tab` and `layouts[id: to] != nil` → `.destinationExists`; `.tab(id, members)`: tab not in source → `.unknownTab`, any member not in `members[from]` → `.memberNotInSource`; source or destination `alert != nil` → `.confirmationPending`; `(directories[from]?.host) != destination.host` → `.differentMachine`.
- Action `case transferTabs(from: LayoutID, to: LayoutID, scope: TabTransferScope)`. Reducer, one turn, **all or nothing**:
```swift
guard let source = state.layouts[id: from], let dest = state.layouts[id: to], from != to else { return .none }
let moving: [TabItem] = scope == .all ? LayoutTransfer.orderedTabs(of: source.layout) : [that tab]   // .tab: guard it exists
let remaining = LayoutTransfer.removing(tabs: ids(moving), from: source.layout)
let grown = LayoutTransfer.appending(moving, to: dest.layout, bootstrapPaneID: PaneID(rawValue: uuid()))
guard remaining.isConsistent, grown.isConsistent else { return .none }          // log error
state.layouts[id: from]?.layout = remaining
state.layouts[id: from]?.windowedPaneIDs.formIntersection(remaining.panes.ids)
if moving has editingTabID { state.layouts[id: from]?.editingTabID = nil }
state.layouts[id: to]?.layout = grown
// members: ordered, in this same turn
let moved = scope == .all ? (state.members[from] ?? []) : members
let kept  = (state.members[from] ?? []).filter { !moved.contains($0) }
state.members[from] = kept.isEmpty ? nil : kept
let joined = (state.members[to] ?? []) + moved.filter { !(state.members[to] ?? []).contains($0) }
state.members[to] = joined.isEmpty ? nil : joined
// hibernation: drop the moved tabs' bookkeeping, then re-derive under the destination id
var cancels: [Effect<Action>] = []
for tab in moving {
  if state.hibernationArmedTabs.remove(tab.id) != nil { cancels.append(.cancel(id: HibernationTimerID.tab(tab.id))) }
  state.hibernationDeferralLogged.remove(tab.id); state.wakeRequestedTabs.remove(tab.id)
}
return .concatenate(.merge(cancels), reconcileHibernation(&state))
```
  No `layoutChangeObserver` call (the manager drives the side effects), no `reap`, no `contentRuntime` call. `@Dependency(\.uuid)` is new to `TerminalsFeature`. B's first member stays primary; a member-less B takes A's order whole (D4).

**`WorktreeContentHost`**
- `pendingAgentOSCNotifications` keeps its payload: `[UUID: (task: Task<Void, Never>, title: String, body: String)]`.
- `struct TransferredSurfaceState` (nested): `surfaceIDs: Set<UUID>`, `tabIDs: Set<TabID>`, `notifications` (order as held, newest first), `surfaceStates` (the same instances), `lastCustomNotificationAt`, `heldOSC: [UUID: (title: String, body: String)]`, the four close-intent sets, `dormant: Set<UUID>`, `completedScriptTabs`, `scriptLaunchDirectories`, `tabProgress`.
- `func relinquish(_ tabs: [TabItem]) -> TransferredSurfaceState`: removes every listed entry for those surface/tab ids from this host and returns it; cancels the held OSC tasks (payload goes in `heldOSC`); removes the ids from `lastSweptContentIDs` and `lastDormantContentIDs`; drops `lastBlockingScriptTabByKind` entries naming a moved tab; clears `lastEmittedFocusSurfaceId` if moved. **Calls no `on…` closure.** Precondition (manager refuses otherwise): no moved tab is in `blockingScripts`.
- `func adopt(_ state: TransferredSurfaceState)`: unions everything in; `lastSweptContentIDs.formUnion(surfaceIDs)`, `lastDormantContentIDs.formUnion(dormant)`; notifications merged newest-first by `createdAt` (stable: this host's entry first on a tie), then `trimNotificationsToRetentionLimit()`; a moved `WorktreeSurfaceState` instance wins over one already registered; re-holds each `heldOSC` through `handleAgentOSCNotification`; `reconcileDormantWatchers()`. Calls no `on…` closure.
- `static func bare(_ tabs: [TabItem], runtime:) -> TransferredSurfaceState` for a source with no host: ids only, `dormant` = moved ids with no renderer.

**`WorktreeTerminalManager.transferTabs(from:to:context:scope:)`** — one synchronous main-actor turn; no `await`, no `Task`, between steps 2 and 8.
```
1  refuse (emit .tabsTransferFailed, change nothing) when:
     isEndingAllSessions → .quitting
     state.terminals.transferRefusal(from:to:scope:destination: Directory(context)) != nil
     any moved tab has hosts[from]?.blockingScriptKind(for:) != nil → .scriptRunning
   `moving` = the tabs the reducer will move, read from the store now.
2  let dst = host(for: to, context: context)          // attaches the layout for .tab scope
   let src = hosts[from]                              // never created for the transfer
3  let baggage = src?.relinquish(moving) ?? .bare(moving, runtime:)
4  sendTerminals(.transferTabs(from:to:scope:))
5  if any moved tab is not in layoutState(for: to): assertionFailure; src?.adopt(baggage);
     for .tab scope undo step 2 (hosts.remove(to)?.tearDown(), .detachLayout(to)); emit failed; return
6  dst.adopt(baggage)
   for each moved content with a live GhosttySurfaceView in ContentRuntime.liveValue:
     wireSurface(view, contentID:, layoutID: to)
7  sourceRemoved = layoutState(for: from)?.layout.panes.isEmpty == true
                   && terminals.members[from]?.contains { $0.sessionKey != nil } != true
   persistTransfer(from:to:sourceRemoved:released:)   // §3
8  if sourceRemoved:
       emitProjection(for: from); emitRunStatus(forDirectory:)     // host still present, layout empty
       paneWindows.closeAll(for: from); hosts.removeValue(forKey: from)?.tearDown()
       sendTerminals(.detachLayout(worktreeID: from))
       emit(.worktreeStateTornDown(worktreeID: srcDirectory, layoutID: from))
       lastEmittedCoalescable.removeValue(forKey: .focus(from)); removedByTransfer.insert(from)
       if selectedLayoutID == from { handleManagementCommand(.setSelectedLayoutID(to)) }
   else: handleLayoutChanged(for: from)               // remaining tabs; sweep sees nothing removed
9  handleLayoutChanged(for: to)
   emit(.tabsTransferred(from:to:tabIDs:sourceRemoved:))
```
`src.tearDown()` after `relinquish` is safe: it only stops watchers, cancels the source's remaining OSC tasks and deletes the launch directories still in its map. Never call `removeLayout`, `deleteLayoutSnapshot`-then-kill, `ContentRuntime.remove`, `cleanupSurfaceState` or `handleSurfacesClosed` here. `cancelPendingIdleHooks` is not called: the surfaces are still there.

No view work in M2. `LayoutContentView` / `PaneTabStripView` read the host by the layout they render, and render-host claims (`ContentRuntime.claimRenderHost`) are content-keyed, so the destination mounts the same renderer.

### M2c — a merged task id stays addressable (decides the T11 hand-off)

- `TaskLayoutsFile.mergedTasks: [String: String]` (removed task key → destination key), decoded tolerantly like `activeTasks`, encoded only when non-empty.
- `LayoutsIncrementalWriter.RecordChange.mergedInto(LayoutID)`: as `.delete`, then `file.mergedTasks[key] = dest`, and every entry whose value is `key` is re-pointed at `dest` (chains stay one hop). A `.record` for a key clears that key's entry. After every apply, entries whose destination is not in `file.tasks` are dropped.
- `TerminalsFeature.State.mergedTasks: [LayoutID: LayoutID]`: loaded in `.layoutsHydrated`; set (and re-pointed the same way) by `.transferTabs` with scope `.all`; cleared for an id by `.attachLayout`.
- `commandLayoutID`: `let task = task.map { mergedTasks[$0] ?? $0 }` before the directory check. The check itself is unchanged: a destination on another directory still returns nil ("Task not found"), as T11 decided for ids living elsewhere.
- Step 7 writes `.mergedInto(to)` for scope `.all`, `.delete` for a `.tab` transfer that emptied its source.

## 3. Destructive and persistence paths

| Path | Rule |
|---|---|
| zmx sessions | The transfer kills none, tombstones none, and calls no function listed under "only kill paths" in §1. `ContentRuntime.contents[id]` is the same object before and after. |
| close/settle signals | No `.surfacesClosed`, `.userClosedSurfaces`, `.tabClosed`, `.tabRemoved`, `.blockingScriptCompleted`; no `ScrollbackPersistence.removeFiles`. Guaranteed by `relinquish` running before the store changes and by never sweeping a source that still lists the ids. |
| what moves | Decided from the store at step 1, in the same turn that moves it. A refusal changes nothing (no host created for `.all`; the `.tab` destination is created only after every check passed). Never partial: the reducer writes both layouts or neither. |
| layout file | One `writer.flush(records:)` carrying **both** keys, so no stored state has a tab in neither task or in both. `persistTransfer`: cancel and clear `layoutDirtyTasks` for both ids; capture `layoutFlushTasks` for both; build the changes now (destination: `recordChange(for: to, layout: LayoutPersistence.record(...).layout)`; source: `.mergedInto(to)` / `.delete` when `sourceRemoved`, else `recordChange(for: from…)` with `releasing:`); then `Task { await inflightFrom?.value; await inflightTo?.value; await writer.flush(records: both) }`, registered in `layoutFlushTasks` under both ids with one new generation (the `deleteLayoutSnapshot` pattern). Skip when `layoutsAreReadOnly` (already refused). |
| stored session order | `RecordChange.record` gains `releasing: [SessionKey] = []`: applied after `TaskMembership.storing`, `task.sessions.removeAll { releasing.contains($0) }`. It is the only way a stored session leaves a record that stays; only the transfer passes it, with exactly the session keys the reducer moved out. The destination is written with `members[to]` under `.loaded`, so its stored order is the run's order: B's sessions, then A's in A's order. |
| hydration | `.notReady` until `layoutsLoaded && storedSessions == .loaded`: before that, `.layoutsHydrated`/`loadStoredSessions` would re-add a moved session to its old task and re-append a removed layout. After it, nothing re-reads stored lists. A relaunch must hydrate the destination with the same ordered `sessions` and the same tab order, and no record for a removed source. |
| quit right after | `saveAllLayoutSnapshots` writes hosted layouts only, so a quit before the transfer flush lands would leave the source record holding the same tabs as the destination (hydration then drops one whole layout for the id collision and the next write of it releases its sessions to the reaper). Add `removedByTransfer: Set<LayoutID>` to the manager; `saveAllLayoutSnapshots` seeds `changes` with `.delete` for each (then the hosted records overwrite); `host(for:)` creating a host removes its id from the set. |
| origins | `.delete`/`.mergedInto` of a directory's last task releases that directory's `origins` entry (existing writer rule, same as closing the directory's last tab). Not changed; see §8. |
| timers | The only timer involved is the hibernation grace timer. A stale one (source id) must hibernate nothing and close nothing. Nothing in the transfer is scheduled. |
| prune / delete worktree afterwards | Decided by the **destination** host's directory, as `prune`/`removeLayouts` already do: a moved tab now goes with B's directory and survives A's. No code change; tested. |
| restore prune | `pruneBareSurfacesOnRestore` may run for the destination when step 2 creates its host; it judges only B's own restored tabs because it runs before step 4. The source host is never created for a transfer, so it never runs for A. |

## 4. Edge cases and races

1. **Rewake after the move** (hibernated tab, or grace timer fires later): `makeSurface` and `wireSurface` use the current owner (M2a). Without it a merged tab wakes deaf (no host for the removed id) and a detached tab wires to the source host, where it can never be closed.
2. **Unexpected zmx close probe in flight across the transfer**: acts on the current owner (M2a.2), or does nothing; never on the source id.
3. **Hibernation timer armed under the source id**: cancelled and re-armed under the destination; if it still fires with the source id, `reduceHibernationGraceElapsed` finds no such layout/tab and returns `.none`.
4. **Moved tab visible in the destination but hibernated**: `wakeRequestedTabs` was cleared, so `reconcileHibernation` wakes it once.
5. **Source pane was windowed**: scope `.all` → `closeAll(for: from)`; scope `.tab` → `windowedPaneIDs` intersected, `paneWindows.reconcile` (inside `handleLayoutChanged(for: from)`) closes the stale window. Tabs survive both. Destination focused pane windowed: the tabs appear in that window.
6. **Pending close confirmation** on either layout → `.confirmationPending`. An explicit-close intent already recorded for a moved surface travels with it (`pendingExplicit…`, `pendingUserClose…`), so a close the user already asked for still counts as theirs.
7. **Running blocking script tab in the moved set** → `.scriptRunning` (its completion is reported under the host's directory; moving it could archive or delete the wrong worktree, and leaving looks like a cancel). A completed one moves: its `completedBlockingScriptTabs` flag and launch directory travel, `lastBlockingScriptTabByKind` does not.
8. **Different machines** (`RemoteHost` differs) → `.differentMachine`: after a relaunch the tab would be rebuilt against B's host and its session lost; `killSession` would also spare or hit the wrong side.
9. **Held OSC 9 / custom-notification window**: re-held on the destination with the carried `lastCustomNotificationAt`; never dropped, at worst delayed one hold window.
10. **Unseen counts and notification log**: per-surface counter instances move, so tab badges keep observing; the global indicator count is unchanged; source row projection is emitted empty before its host goes, destination projection after.
11. **Source selected** (manager's `selectedLayoutID == from`) and removed → manager selects `to`. App-level `selectedTask` is M3's; until then `sessionsLinkReducer` sends `selectedTaskRemoved` as it does for any removed task.
12. **Tab creation already scheduled into the source** (`scheduleTabCreation`) lands after a merge: `host(for:)` re-attaches the id as a fresh task with that one tab. Allowed; `attachLayout` clears `removedLayoutIDs` and the alias for it.
13. **Presence report between reducer and next reconcile**: `TaskMembership.reconciled` finds the session already listed in the destination and changes nothing. Provisional members move too, so the ref upgrades in place there (A22).
14. **Agent quits right after a merge**: `settleReplacedOrEndedSession` reads `surfaceIndex` and `members` now, so A's former primary is a tangent of B and settles no task.
15. **Source with no host** (hydrated, never opened): layouts, members and the record move; no baggage; dormant ids seeded via `.bare`.
16. **Empty source, scope `.all`**: zero tabs move, members move, source removed. **`.tab` that empties a member-less source** (shell-only): source removed, as a shell-only task with no tab (Q4).
17. **Already-running shell's `SUPACODE_TASK_ID`**: merge → resolved by the alias (same directory only); detach → still names the source, so bare `tab new` from that shell lands in the source. Id-carrying commands are right in both cases.
18. **Quit in progress** (`isEndingAllSessions`) → `.quitting`.
19. **Reentrancy**: `transferTabs` runs from `TerminalClient.send` inside an effect, never from a reducer body; `appStore.send` in step 4 is synchronous, as `createTabAsync` already relies on.

## 8. Decisions the plan left open, and contradictions

1. **Nothing moves in `ContentRuntime`.** The plan says "moves live content runtimes and their surfaces from one host to another"; the registry is global, so the move is host bookkeeping plus callback re-wiring. The plan's file list also misses `TerminalsFeature.swift` (the action must span two layouts, so it cannot live in `LayoutFeature`), `supacodeApp.swift`, `TerminalSurfaceRecipe.swift`, `LayoutsIncrementalWriter.swift`, `TaskRecord.swift`.
2. **Membership and the record move in M2, not M3** (plan M3: "append A's sessions to B's, delete A's record"). `sessionsLinkReducer` reconciles membership on the very action that moves the tabs, in surface-uuid order, and the writer never drops a stored session; done later, B's order is already wrong and A's sessions are stored twice. M3 keeps: which members ride on a detached tab, refusing the primary, minting the id, selection, UI.
3. **One command, two scopes.** `.tab` is added here so detach (A29) uses the same guarded path instead of a second transfer in M3.
4. **Hibernation needs no re-key** beyond the timers: its state is tab-keyed.
5. **Refused, not handled** (each narrows D8; cj to confirm): tasks on different machines; a moved tab with a running blocking script; any transfer before the layouts have hydrated or while the store is read-only/unreadable; either task showing a close confirmation.
6. **Stale `SUPACODE_TASK_ID`** (T11 hand-off): keep the merged id resolvable through a persisted alias, same directory only. Chosen over falling back to the shown task, which would let an id-less command from a stale shell act on a task it never named. A detached tab's shell keeps naming its source; accepted, no alias is possible while the source exists. M2c can ship with M3 instead if cj prefers one fewer persisted field now.
7. **The source host is never created for a transfer**, so a never-opened task's bare restored tabs skip `pruneBareSurfacesOnRestore` and arrive unpruned. Chosen so a merge can never trigger that prune's kill.
8. **`layoutsLoaded` flag** is new state; cheaper than making late hydration transfer-aware.
9. **Origins**: merging away a directory's last task releases that directory's v1 `origins` entry to the reaper, as closing its last tab does today. The directory still exists, so cj may want the origin kept; changing it is a writer rule change outside M2.
10. **Quit-save now deletes transfer-removed ids.** Scoped to `removedByTransfer`, not all of `removedLayoutIDs`, to leave the existing prune/empty-task paths alone.
11. Found while reading, not fixed here: `cancelPendingLayoutSaves` cancels flush tasks that do not check cancellation, so a flush created but not yet on the writer queue can still land after the quit write; `.layoutsHydrated` does not skip `removedLayoutIDs`.
12. Full `make test` is recommended for M2 although ground rule 4 does not list it.
