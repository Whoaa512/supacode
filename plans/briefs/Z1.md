## 2. Design

### 2.1 Z1a — menu commands target the shown task

New, in `AppFeature.swift` next to `shownTask`:

```swift
/// The terminal on screen, for commands that have no id of their own.
struct ShownTerminal: Equatable {
  let directory: DirectoryContext
  /// Nil when the directory is shown with no task (its empty state).
  let layoutID: LayoutID?
}

extension AppFeature.State {
  var shownTerminal: ShownTerminal? {
    if let orphan = repositories.orphanTaskID, let picked = repositories.selectedTask,
      AppFeature.hasTask(orphan, state: self)
    {
      return ShownTerminal(
        directory: AppFeature.directoryContext(forTask: orphan, directoryID: picked.directoryID, state: self),
        layoutID: orphan)
    }
    guard let worktree = repositories.worktree(for: repositories.selectedWorktreeID), !worktree.isMissing
    else { return nil }
    return ShownTerminal(
      directory: DirectoryContext(worktree: worktree),
      layoutID: commandLayoutID(forDirectory: worktree.id))
  }
}
```

Reducer: every case listed in §1 replaces its `guard let worktree … !worktree.isMissing` +
`state.layoutID(forDirectory:)` + `DirectoryContext(worktree: worktree)` with
`guard let shown = state.shownTerminal, let layoutID = shown.layoutID else { return .none }` and `shown.directory`.
`.newTerminal` is the one exception: in Z1a it keeps its landing id
(`shown.layoutID ?? state.layoutID(forDirectory: shown.directory.worktreeID)`), in Z1c that becomes the mint.
`.newTerminal`'s `shouldRunSetupScript` reads `sidebarItems[id: shown.directory.worktreeID]` (nil for an orphan →
false). Do not touch cases that carry their own worktree id (`.focusTerminalSurface`, `.closeTerminalSurface`,
`.closeTerminalTab`, `.selectTerminalTab` delegate, `jumpToLatestUnread`, scripts, `runBlockingScript`): they are
not "the shown terminal".

Scope rule: only the terminal commands above. Directory features (run/stop script, open-in, reveal, inspector,
`$EDITOR` tab) stay on `selectedWorktreeID`: an orphan has no directory to give them (open question 13).

Views:
- `WorktreeDetailView.body`: `let hasShownTerminal = hasActiveWorktree || repositories.orphanTaskID != nil`
  (repositories-only read; no new layout observation). Pass it to `applyFocusedActions` and use it instead of
  `hasActiveWorktree` for exactly: `newTerminalAction`, `renameTabAction`, `splitTerminalAction`,
  `toggleWindowModeAction`, `toggleSplitZoomAction`, `equalizeSplitsAction`, `focusSplitAction`,
  `focusRelativePaneAction`, `closeTabAction`, `closeSurfaceAction`, the four search actions. Everything else keeps
  `hasActiveWorktree`. These closures capture only the store, so no `token` is needed (FocusedAction rules).
- `hasFocusedTab(in:worktreeID:)` → `hasFocusedTab(in state:)` reading `state.shownTerminal?.layoutID`. It already
  reads the layout in this body today; no new invalidation source.
- `PaneWindowManager`: `isWorktreeSelected` becomes `state.shownTerminal?.layoutID == worktreeID`.

### 2.2 Z1b — agent commands take a task

Wire shape (same path pair T11 chose for worktree deeplinks):
`supacode://agent/<worktree-id>/task/<task-id>/<kind>/<action>`; socket queries `agentRead`/`agentExplain` take
`taskID`. Without the pair nothing changes on the wire.

App:
- `Deeplink.agent(worktreeID:agent:action:task: LayoutID?)`.
- `DeeplinkClient.parseAgent`: if `pathSegments.count >= 5 && pathSegments[1] == "task"`, parse
  `LayoutID(external: pathSegments[2])` (nil → return nil, logged) and read kind/action from `[3]`/`[4]`; else as
  today with `task: nil`.
- One resolver replaces the five `sidebarItems[id:]?.surfaceIDs` reads (in `AppFeature+AgentCommands.swift`,
  `static` on `AppFeature` so `supacodeApp.swift` can call it through `store.withState`):

```swift
/// The surfaces an agent command may address, in the row's order.
static func agentSurfaceIDs(
  worktreeID: Worktree.ID, task: LayoutID?, state: State
) -> (ids: [UUID], error: String?) {
  guard let item = state.repositories.sidebarItems[id: worktreeID] else {
    return ([], "Worktree not found: \(worktreeID.rawValue)")
  }
  let index = surfaceIndex(state: state)
  guard let task else {
    // No task named: the shown task's surfaces first, then the rest, order kept.
    let shown = state.commandLayoutID(forDirectory: worktreeID)
    let all = Array(item.surfaceIDs)
    return (all.filter { index[$0]?.layoutID == shown } + all.filter { index[$0]?.layoutID != shown }, nil)
  }
  let directory = state.terminals.directories[task]?.worktreeID ?? storedTask(task, state: state)?.directory.worktreeID
  guard hasTask(task, state: state), directory == worktreeID else { return ([], "Task not found.") }
  return (item.surfaceIDs.filter { index[$0]?.layoutID == task }, nil)
}
```

- `agentPresenceKey`, `promptAgent`, `sendKeysToAgent`, `resumeAgent`, `reportAgentMetadata`, `renameAgentEffect`,
  `handleAgentDeeplink` gain `task: LayoutID?` and go through it. `resumeAgent`'s "already running" check and its
  candidate lookup both use the narrowed list. `handleAgentReadQuery`/`handleAgentExplainQuery` parse
  `params["taskID"]` (`LayoutID(external:)`; unparsable → `ok: false`, "Task not found.") and use it for the agent
  lookup; agent read with no `agent` param reads the focused surface of
  `commandLayoutID(externalWorktreeID:externalTaskID:)`.
- `AgentQueryResponse.rows` and `AgentResumeCandidateQueryResponse.rows` gain a `tasks: [UUID: LayoutID]` argument
  (callers pass `AppFeature.surfaceIndex(state:).mapValues(\.layoutID)`) and emit `Key.taskID = "taskID"`:
  `layoutID.externalID`, or `""` when the surface has no entry.

CLI:
- `AgentCommand.Key.taskID`/`ResumeKey.taskID = "taskID"`; append to `Key.all`/`ResumeKey.all` and to
  `omittedWhenEmpty` (JSON gains a trailing optional field; `listLine` columns unchanged).
- `@OptionGroup var taskOption: TaskOption`-style `--task` (plain `@Option(name: .long) var task: String?`; the
  `TaskOption` help text is about worktrees) on `Rename`, `Wait`, `Prompt`, `SendKeys`, `Read`, `Explain`, `Resume`,
  `ReportMetadata`.
- `resolve(target:agentKind:task:environmentTaskID:in:)`:
  1. exact name match wins, as today (names are unique);
  2. filter by worktree/branch/title and `agentKind`, as today;
  3. if `task` is given, keep rows whose `decoded(row[taskID]) == decoded(task)`;
  4. if more than one row remains and exactly one has `taskID == environmentTaskID`, take it;
  5. zero → `notFound`; more than one → `ambiguous`, candidates now show the task id.
  `resolveCandidate` gets steps 3–5 too.
- Every agent URL builder takes a `WorktreeTarget` (`worktreeID` + the resolved row's `taskID`, nil when empty) and
  writes `target.urlSegment`; `agentReadRows`/`agentExplainRows` send `target.queryParams`. So a name-addressed
  command also reaches exactly that agent, which it does not today.

### 2.3 Z1c — the seam goes optional; a first tab mints a task

`TerminalsFeature.State` (same extension):
- Delete `layoutID(forDirectory:)`, `recordedLayoutID(forDirectory:)`, `ownKeyLayoutID(forDirectory:)`,
  `displayLayoutID(forDirectory:)`.
- Add:

```swift
/// Where a directory-addressed command lands: the task the directory shows, else a recorded task of this
/// directory that holds no tab (an emptied task that still lists a session). Nil: the directory has no task.
func landingLayoutID(forDirectory directoryID: Worktree.ID) -> LayoutID? {
  if let task = task(forDirectory: directoryID) { return task }
  guard let recorded = activeTasks[directoryID], directories[recorded]?.worktreeID == directoryID else { return nil }
  return recorded
}

/// A task stored under its directory's path: the shell task a migrated directory kept. A comparison only;
/// no id is ever made from a directory.
static func isOwnKey(_ layoutID: LayoutID, ofDirectory directoryID: Worktree.ID) -> Bool {
  layoutID.persistenceKey == directoryID.rawValue
}
```
- `isTask(_:onDirectory:)` = `holdsTabs(id) && directories[id]?.worktreeID == directoryID`. No guess.
- `task(forDirectory:)`: step 3 becomes
  `layoutIDs(onDirectory:).first { Self.isOwnKey($0, ofDirectory: directoryID) && holdsTabs($0) }`. Order of the
  four steps unchanged (keeps what a migrated, never-reselected directory shows after relaunch).
- `recordActiveTask`: `active = Self.isOwnKey(layoutID, ofDirectory: directoryID) ? nil : layoutID`. Unchanged
  behaviour, so the stored `activeTasks` format and write pattern do not change.
- `commandLayoutID(…shown:)`: `let resolved = shown ?? landingLayoutID(forDirectory:)` (optional);
  `candidates = [resolved].compactMap { $0 } + layoutIDs(onDirectory:).filter { $0 != resolved }`; rest unchanged.
  It now also returns nil for "no task named and the directory has none". Callers tell the two nils apart by
  whether they passed a `task`.

`AppFeature.State`:
- `layoutID(forDirectory:) -> LayoutID?` = `commandLayoutID(forDirectory: worktreeID)`. One meaning for the seam:
  what a bare command on the directory means (so every remaining caller is also right in the echo window).
- `layoutID(forDirectory:holding:) -> LayoutID?` = `commandLayoutID(forDirectory:, holding: [id])` (no `??`).
- `detailLayoutID` = `taskOnMissingDirectory ?? terminals.landingLayoutID(forDirectory:)`. In
  `selectedWorktreeChanged`, `landing` is `terminals.landingLayoutID`.
- `worktree(forLayout:)`: delete the second (scanning) loop; `terminals.directories[layoutID]` is the only answer.
- `persistedLayout(forDirectory:)`: optional-chain the seam.
- New:

```swift
/// The task a first-tab command on this directory is waiting on, if one was minted and has no tab yet.
func pendingFirstTab(forDirectory id: Worktree.ID) -> LayoutID? {
  pendingTaskLaunches.last { $0.directoryID == id && $0.followsDirectory }?.layoutID
}
```
- `worktreeNewAckDirectory(forLayout:)` and the `.terminalEvent(.initialTabCreationFailed)` closure compare against
  `layoutID(forDirectory: boundID) ?? pendingFirstTab(forDirectory: boundID)`. Without this a failed first tab on a
  new worktree never fails its `worktree new` ack.
- `confirmedLayoutID` takes `target: LayoutID?`. Non-nil: unchanged, minus its "no record" branch, which becomes
  `commandLayoutID(forDirectory:task:) == target`. Nil target (dialog raised for a directory with no task): valid
  only while `task == nil && commandLayoutID(forDirectory:) == nil`; the caller then mints. Anything else → nil →
  "Task not found" (T11 r3's rule, kept).

Minting (`AppFeature+Sessions.swift`, beside `launchSessionTab`):

```swift
/// The layout a tab-creating command on a directory goes to: its task, else one minted for it. The mint is
/// remembered until its first tab exists, so a second command in that window joins it instead of minting again.
static func firstTabLayoutID(forDirectory directoryID: Worktree.ID, state: inout State) -> LayoutID {
  if let existing = state.layoutID(forDirectory: directoryID) ?? state.pendingFirstTab(forDirectory: directoryID) {
    return existing
  }
  @Dependency(\.uuid) var uuid
  let layoutID = LayoutID(task: uuid())
  state.pendingTaskLaunches.append(
    PendingTaskLaunch(layoutID: layoutID, directoryID: directoryID, primary: nil, followsDirectory: true))
  return layoutID
}
```
- `PendingTaskLaunch` gains `var followsDirectory = false`. `launchSessionTab`'s `isShown = false` loop skips
  nothing (the flag is unused for these); its `removeAll { $0.layoutID == layoutID }` is unchanged.
- `showLaunchedTaskIfReady`: ready entries are removed as today. Then: if a ready entry with
  `!followsDirectory && isShown` exists → `selectTask` as today. Else, for the last ready `followsDirectory` entry,
  if `state.repositories.selectedWorktreeID == entry.directoryID && state.repositories.selectedTaskID == nil` →
  `.run { await terminalClient.send(.setSelectedLayoutID(entry.layoutID)) }`. Otherwise nothing: a first tab never
  moves the selection, it only tells the terminal which layout the already-selected directory now shows (the
  selection sent `setSelectedLayoutID(nil)` while it had no task).

/// Tasks the stored file puts on this directory that nothing at runtime names (not hydrated yet, or dropped
/// at hydration). Named by their record, never guessed from the directory.
private func removeStoredLayouts(forDirectory directoryID: Worktree.ID, remoteHost: RemoteHost?) {
  let known = Set(layoutIDs(onDirectory: directoryID))
  let stored = appStore?.withState { state in
    AppFeature.storedTasks(state: state).filter { $0.directory.worktreeID == directoryID }.map(\.id)
  } ?? []
  for layoutID in stored.sorted(by: { $0.persistenceKey < $1.persistenceKey }) where !known.contains(layoutID) {
    removeLayout(layoutID, directoryID: directoryID, remoteHost: remoteHost, fromStoredRecord: true)

}

## 3. Destructive and persistence paths

1. **`removeLayouts(forDirectory:)`** (archive/delete of a worktree). A task is torn down only if (a) a host or a
   `directories` entry puts it on the directory, or (b) its stored record's `directory.worktreeID` is the
   directory and it is not in `removedLayoutIDs`. Never by key shape, never by "what the seam resolves to". The
   `onlyIfStoredOn` check in `deleteLayoutSnapshot` stays as the second lock.
2. **Close commands** (`.closeTab`, `.closeSurface`, deeplink closes). Target = `shownTerminal.layoutID` read in the
   reducer at the moment the action runs, or the owner of the id the command carries. Nil → no command is sent.
   No close ever falls back to "the directory's other task".
3. **`isTask` without the guess.** A layout with no `directories` entry is no directory's task. Consequence to
   accept: it is not shown by a directory selection and not targeted by a bare command, and it is not pruned.
4. **First-tab mint writes nothing by itself.** `PendingTaskLaunch(primary: nil)` lists no member, so no session
   list is created or reordered; the task is persisted only once its tab exists (existing snapshot path). Z1 does
   not touch `members`, `hydratedMembers`, `TaskMembership` or any ordered list; if a diff shows otherwise, stop.
5. **`activeTasks`.** Still nil for an own-key task, the minted id otherwise; written only through
   `recordActiveTask`. Hydration's `file.activeTasks` loop is unchanged. No schema change, no migration.
6. **Mint never reuses a stored id.** A first tab pressed before hydration mints a fresh `LayoutID(task:)`; stored
   tasks of that directory hydrate beside it untouched.
7. **Agent `resume` types a command into a terminal.** With a task named it may only pick a candidate on that
   task's surfaces; a named task that is unknown or on another directory refuses, it does not widen to the
   directory.
8. **No timers.** Z1 adds no delay, debounce or clock. The pending first-tab entry is cleared by state (its tab
   exists), never by time.

## 4. Edge cases and races

| Case | Required behaviour |
|---|---|
| Cmd-T twice (or `worktreeCreated` then Cmd-T) before the first tab exists | One mint: the second call returns `pendingFirstTab`. One task with two tabs. |
| First tab fails to host (`initialTabCreationFailed`) | Pending entry stays; the `worktree new` ack fails through `pendingFirstTab`; the next Cmd-T reuses the same id. No empty task is stored. |
| User selects another directory before the minted tab appears | No `setSelectedLayoutID` is sent for the mint; coming back resolves it through `task(forDirectory:)` (step 4). |
| User selects a task (`selectedTaskID != nil`) before the minted tab appears | Follow is skipped; the pick stands. |
| Directory selected, selected task emptied but lists a session, Cmd-T | Lands in that task (`landingLayoutID` recorded branch / `shownTask`), no mint. |
| Recorded `activeTasks` entry names another directory's task or nothing | `landingLayoutID` nil → empty state; Cmd-T mints. Closes T10 r1's cross-directory note. |
| Task selected, terminal has not echoed it into `activeTasks`, then a menu chord | Chord goes to the selected task (`commandLayoutID` → `shownTask`), not the recorded one. |
| Orphan task shown | All §2.1 commands enabled and sent to it with `DirectoryContext(orphan:)`; `runSetupScriptIfNew` false; directory features stay disabled. |
| Orphan task removed while shown (`hasTask` false) | `shownTerminal` nil → commands no-op, menu disabled on the next body run (the stale pick itself is dropped where `AppFeature+Sessions.swift` checks `hasTask` on the selected task). |
| Selected roster directory is missing on disk, with or without a task picked on it | Unchanged: all menu terminal commands refused (see §8). |
| Pane window chord while an orphan task is shown | `isWorktreeSelected` true for that task's layout. |
| Confirm dialog for `tab new --input` on a task-less directory; a task appears before confirm | Refused, "Task not found". Cancel leaves no pending entry (mint happens only on confirm). |
| Bare `tab close`/`pane …` on a task-less directory | Existing not-found error, `ok: false`; nothing minted. `tab list` answers an empty list. |
| Agent command, two tasks on one directory, same harness, no task named | App: the shown task's agent, else row order. New CLI: `ambiguous` unless `--task`, a name, or the environment's task singles one out. |
| Agent command naming a task of another directory / unknown / unparsable | "Task not found.", `ok: false`, nothing typed. |
| Old CLI or hand-written deeplink without the task pair | Works as before (directory-scoped, shown task first). |
| Agent row whose surface is in no task (`surfaceIndex` miss) | `taskID` empty; `--task` never matches it. |
| Worktree archived before hydration, directory has three stored tasks | All three records removed, no other directory's record touched, even one whose key is this directory's path but whose record names another directory. |
| Layout state without a `directories` entry (tests, or attach not landed) | Not a task of any directory; never selected, targeted, or torn down by directory. |

## 8. Decisions the plan left open, and contradictions

1. **Own-key preference kept as a comparison** (`isOwnKey`), not dropped. A32 forbids *constructing* a `LayoutID`
   from a directory; comparing `persistenceKey` to the directory id does not. Dropping it would change which task
   a migrated directory shows after relaunch and force `activeTasks` writes on every own-key selection.
2. **First tab on a task-less directory mints a shell task** (`LayoutID(task:)`), per D2 ("starting an agent or
   shell mints one"). The plan only said "delete the fallback"; without a mint, Cmd-T, `tab new` and
   `worktreeCreated` would have nowhere to land.
3. **The mint follows the selected directory; it never selects.** `selectTask` would yank a user who moved on, and
   would turn a directory selection into a task pick (T10 r2 semantics).
4. **The app seam's meaning is the command answer** (`commandLayoutID`, shown task included). Narrows T11 r1's
   echo-window fix from "menu sites" to every bare-directory caller, with one function instead of two.
5. **Missing-on-disk roster directory: menu commands stay refused**, also when a task is shown on it
   (`taskOnMissingDirectory`). The plan asks only for the orphan case; enabling close/search there is safe but is
   new behaviour nobody asked for. Follow-up, not Z1.
6. **Directory features stay disabled for an orphan** (open question 13: they follow the task's directory, and an
   orphan's is not in the roster).
7. **Agent task narrowing covers the whole family** (rename, wait, explain, metadata too), not only
   prompt/send-keys/resume/read: they share one lookup, and leaving three on the old one would be the same bug.
8. **Agent task shape**: `agent/<wt>/task/<id>/<kind>/<action>`, `taskID` on the agent rows, CLI ambiguity error
   instead of an arbitrary pick, environment task as tie-break only. No env default that silently narrows a
   command aimed at another worktree (T11's rule).
9. **Agent commands on an orphan directory still fail "Worktree not found"** (they key off the worktree row).
   Unchanged; a follow-up if wanted.
10. **`removeUnnamedLayout` replaced, not just retyped.** Its guess depended on the fallback. The stored-record walk
    is stricter on identity and also covers minted tasks of an unhydrated directory, which the guess missed. It
    still kills no zmx session for an unhydrated task (no surface ids known), as today.
11. **No rename of `WorktreeTerminalManager`/`WorktreeContentHost`.** The plan allows it only as a pure rename
    commit; it touches every terminal test and widens upstream drift (sizing TODO) for no behaviour. Leave it for
    a separate decision.
12. **`init(legacyWorktreeKey:)` stays `internal`**, guarded by the `rg` gate and its comment: two migrator files
    and the test support need it.
13. **Contradiction with the plan's label**: Z1 is listed "Mechanical". Z1a–Z1c are complex and Z1c touches a
    destructive path (§3.1); treat it under the destructive-slice gate (full `make test`).
14. **Contradiction with T10 r1's note** that `displayLayoutID` and the command seam differ: after Z1c they are one
    function (`landingLayoutID`), so the view and commands cannot disagree.
