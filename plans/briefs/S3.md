## 2. Design

No new or changed types, fields, actions or views. The behaviour to pin, as
one state walk for a task `T` on directory `/repo/main` (name `main`):

| Step | Inputs | Row `.task(T)` |
|---|---|---|
| 0 shell-only | `taskSnapshots=[T]`, no agent, `taskSessions[T]` absent | title `main`, `primary nil`, `status nil`, `isSynthetic false`, `isLive true`, lifecycle active |
| 1 agent, unreported | + snapshot `sessionRef nil` on T's surface | title `New session`, `primary nil`, status = agent's, `isSynthetic true` |
| 2 ref reported, not yet listed | snapshot `sessionRef "a"`, `taskSessions[T]` still absent | `primary a`, title `New session` |
| 3 listed | `taskSessions[T]=[a]` | unchanged from 2 (no write) |
| 4 indexed | `sessionSummaries` has `a` | title = summary's, `isSynthetic false`, `createdAt` = summary's |
| 5 agent ended, tab open | snapshot gone | title stays summary's, `status nil`, location = first-tab anchor, active |
| 6 last tab closed | `taskSnapshots=[]` | `isLive false`, lifecycle = primary's mark, activation resumes `a` into T |

At every step: `sessionItems.ids == [.task(T)]` (never an `.implicit` or
`.provisional` row for the agent), `sessionsSidebarStructure.subRows` empty,
a `sessionSelection` of `.task(T)` unchanged, `selectedTask` unchanged.

App side of steps 1–3 (already wired in `sessionsLinkReducer`):
`surfacesChanged` → `sessionSnapshotsChanged` + `membersChanged`
(`[.provisional]`, no store write) → ref → `membersChanged([.session(a)])`
→ `LayoutChangeObserver.sessionsChanged(T)` once → `taskSessionsChanged`.

Conditional fixes (only if the named test is red):
- Title does not fall back to the directory (tests 1, 3): the fallback chain
  in `taskDraft` must end `... ?? group.tabs?.title` before `existing?.title`.
  Fix there, nowhere else.
- An extra row appears for the agent (test 1): the fault is in
  `SessionGroups.init` (agent must be appended to `tasks[layoutID].agents`
  when the task is known through `tabs`), not in the view.
- Selection lost (tests 2, 7): the fault is a row id change; do not add
  selection-moving code, restore the stable id.
Anything else red: stop and report; do not redesign.

## 3. Destructive and persistence paths

S3 adds no path. A shell-born task now reaches these existing ones; each
must keep its rule and gets a pin test (section 5).

1. **Primary quit closes the task's tabs** (`settleReplacedOrEndedSession`
   → `settleTask` → `LayoutFeature` `.closeAllTabsRequested`). Rule, all
   read from current state at the event: the ended session is
   `members[task].first`; no other presence record sits on a surface of that
   task; the end is Pi `shutdownReason == "quit"` with a `pid`; the record
   tracks no other pid; `terminals.storedSessions != .pending`. Otherwise
   mark only, or nothing. For a shell-born task this means the user's plain
   shell tabs in that task close with the agent (behind the
   `confirmCloseTab` setting; an idle shell is not "busy"). This is T9's
   tested rule (`thePrimaryQuittingAloneSettlesTheTask` has a plain shell
   second tab). Kept; see section 8, item 1.
2. **An unreported agent's end closes and marks nothing**: the guard
   `let oldRef = record.sessionRef` fails. A shell-only task stays shell-only.
3. **Non-Pi or remote end**: bare/pid-less → `settleSession(key)` only. No
   tab closes.
4. **Last tab closed** (`removeTaskIfEmptied`): the task is removed only when
   runtime `terminals.members[task]` lists no session **and**
   `layoutsWriter.storedSessions(of:)` returns an empty list (nil = unreadable
   = keep). A shell-born task that has listed a session is kept with an empty
   layout; one whose agent never reported is removed (Q4). Nothing is killed
   by the removal.
5. **Store order**: the first session of a shell-born task is written by the
   existing `sessionsChanged` → debounce → `.record` path. The stored record
   had `sessions == []`, so `TaskMembership.storing` appends; later members
   append behind it; nothing is moved or dropped. Hydration
   (`.layoutsHydrated`) must return the same order. While
   `storedSessions == .pending` the run's list is queued
   (`pendingMembership`), not written (T9 r5/r6); unchanged.
6. **Provisional members are never stored** (`membersChanged` compares
   session keys only).
7. **Auto-settle** (`autoSettleSessions` / `TaskIdleness`): a task with an
   open tab is never settled and nothing is ever closed by it. No timer in
   S3; the tests use no clock except the manager harness's `TestClock`
   debounce.
8. **Sidecar**: S3 writes nothing to `sessions`. A primary that joins already
   marked settled keeps its mark (section 4, E6).

## 4. Edge cases and required behaviour

- E1 Agent ends before any turn, tab still open (`taskSessions[T]=[fresh]`,
  no summary, no agent): row stays (it has a location), title is the
  directory name again, `primary == fresh`, also after a
  `droppingUnindexedEnded` pass. Not removed, not retitled "New session".
- E2 A second agent starts later in the same task: appended behind the
  first; title stays the first's (or, if the first was never indexed, the
  second's once indexed: S1's "first member that did"). The primary does not
  change. Do not "promote".
- E3 Harness with no session source (all but Pi): steps 0–3 happen, step 4
  never does; on end the row falls back to the directory title with a
  primary listed. Accepted (section 8, item 4).
- E4 Ref reported and tab closed in the same turn: `removeTaskIfEmptied`
  reads the reducer's `members` at that moment. If the session is listed the
  task is kept; if `membersChanged` has not run the task is removed and the
  session shows as an `.implicit` history row once indexed. Both are correct;
  no session is lost and nothing is killed. Do not add a delay or retry.
- E5 Tab closed with `membersChanged` applied but the debounced write not
  yet flushed: the task must be kept (runtime members decide) and the next
  flush must carry `sessions == [key]`. Test 9b.
- E6 The first agent is a hand-resumed session already marked settled
  (`pi --resume` in the shell): row is Active while a tab is open
  (`appendTaskDrafts`), moves to Settled when the last tab closes, and no
  sidecar write happens on join. Not lifted here (section 8, item 3).
- E7 Cmd-N while a shell-only task is on screen mints a **new** task on that
  directory (`currentTaskContext`); the shell-only task stays sessionless.
  Only an agent started inside one of its tabs converts it. Covered by
  `newSessionMintsATaskInTheCurrentDirectoryWithTheDefaultAgentAndNoPrompt`;
  no new test.
- E8 Own-key task (`LayoutID(legacyWorktreeKey:)`, the directory's default
  layout, and T6's leftover-shell task): same walk, same id. No special case.
- E9 Orphan/remote directory: title is the last path component of the
  recorded path; nothing else differs.
- E10 `createdAt` changes once at step 4 (task's date → session's), so the
  row re-sorts once (a legacy shell task, sorted last by `legacyCreatedAt`,
  moves up). Selection is by id and must survive. Intended (section 8, item 2).
- E11 Relaunch at step 5: `record.sessions == [a]` hydrates into
  `members[T]`; with the index loaded the row is titled by `a`, Active, no
  status, activation is `focusTask` (not resume).
- E12 Sub-agent of the first agent (follow-up, fixed in T9): a nested
  process's events are ignored (`isFromNestedAgent`), so it neither becomes
  the primary nor ends the task. Already tested; no new test.
- E13 Performance: the switch adds no pass. `RepositoriesFeatureSessionsScaleTests`
  must stay unmodified and green (A26).

## 8. Decisions left open by the plan, and conflicts

1. **Quit in a shell-born task closes the user's shells. Kept, flagged.**
   D4 says the task "becomes an agent task"; A19/A37 and T9's tested rule
   then close every tab on a positively identified primary quit. S3 keeps
   that (no special case, no provenance field) and pins it (8a–8c). It is
   the one behaviour here that can surprise: the migrated per-directory
   shell task loses its idle shells when an agent run in one of them quits.
   If cj does not want it, the smallest rule decidable from current state is
   in `settleReplacedOrEndedSession`: call `settleTask` only when the task's
   layout holds no tab other than the quitting agent's; otherwise mark only.
   That narrows T9 for every task, so it is cj's call, not S3's.
2. **`createdAt` moves once** when the first member is indexed. Kept as S1
   defined it (oldest indexed member). Taking `min(tabs.createdAt, indexed)`
   would pin migrated agent tasks to the bottom through `legacyCreatedAt`,
   and the date would move at tab close instead.
3. **A settled mark on a joining primary is not lifted** (E6). The app's own
   resume path and `replaceSession` lift marks; a hand-resume into a shell
   does not, as before tasks existed. Lifting on presence would write the
   sidecar from launch-time restore; out of scope. Row placement is already
   right while a tab is open.
4. **A primary that is never indexed** (non-Pi harness, or quit before a
   turn) stays the task's primary: the row falls back to the directory
   title, and once the last tab closes the record stays with no row. This is
   T7's rule (a listed session is never removed) and the follow-up "a task
   with a member that has no summary"; not changed here, since absence from
   the index cannot yet be told from "not scanned". Not a contradiction of
   Q4 in code terms (the task lists a session), but its effect is a
   shell-looking task that is not deleted on last-tab close.
5. **No view change.** The plan lists only the structure file and title
   derivation. A shell-only row still has an empty context menu and the
   accessibility label "Live session"; left for S2/Z2.
6. **Plan text superseded by Progress**: "the T5 shell-only row is replaced
   by the task row" no longer describes anything; since S1 there is one
   `.task` row throughout. The plan's Files/Steps for S3 are met by S1's
   code; S3's diff is tests plus the Progress entry.
7. Follow-ups file: no item names S3. The index-absence item says "whichever
   slice next touches the session index"; S3 does not touch it.
