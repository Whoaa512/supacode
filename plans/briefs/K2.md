## 1. What exists (by symbol)

- Chord: `AppShortcuts.nextSessionNeedsMe` → `TerminalCommands` (`nextSessionNeedsMeAction`) →
  `WorktreeDetailView` sends `AppFeature.Action.nextSessionNeedsMe` → `AppFeature.handleNextSessionNeedsMe`
  (`AppFeature+Sessions.swift`).
- Today's pick: `SessionsSidebarStructure.nextNeedingAttention(from:items:)` walks `liveIDs` after the current
  **row** and returns the first row with `allowsAttentionNavigation` and status `.needsYou`/`.doneUnseen`. The
  handler then focuses that row's `location`.
- A task row's `status`/`allowsAttentionNavigation`/`location` are its *leading* agent's (`taskDraft`, sorted by
  `(urgency, allows, same-location)`). That is the gap:
  - leader `.working` + tangent `.doneUnseen` → row is `.working` → skipped; tangent unreachable.
  - leader `.needsYou` from `.error` (`allowsAttentionNavigation == false`) + tangent `.doneUnseen` → skipped.
  - two needy agents in one task: the second is reached only after every other row, because the cursor is the row.
- Per-agent facts: `RepositoriesFeature.State.sessionSnapshots: [SessionLiveSnapshot]` (`location`, `status`,
  `allowsAttentionNavigation`, `member`), kept current by `sessionsLinkReducer` on every `.terminals` /
  `surfacesChanged` action. Sorted by surface uuid string, then harness.
- Member order: private `members(of:agents:)` in `SessionsSidebarStructure.swift` (listed `taskSessions`, then
  unlisted agents). Same order as `subRows`.
- Cursor inputs: `AppFeature.focusedSurfaceID(state:)`, `AppFeature.focusedSessionRowID(state:)` (the selected
  layout's `.task` row when it exists), `sessionSelection`.
- Focus: `RepositoriesFeature.Action.Delegate.focusSession(SessionLocation)` → `AppFeature.focusSession`
  (`selectTask` + `terminalClient.focusSurface`, by the location's own layout; works for a non-selected task).
  `selectSessionRow(_:)` moves the highlight and recomputes sub-rows. `AppFeature.hasTask(_:state:)`.
- Focusing a surface clears its attention (`AgentPresenceFeature.clearAttention`), so a visited target
  normally leaves the candidate set by itself.

## 2. Design

Nothing is cached: the target is computed at key press from current state. No new state field, no new
action, no structure field (a cached list would rewrite `sessionsSidebarStructure` on every status flip and
break A26's write-free pass).

### 2.1 `SessionsSidebarStructure.swift`

Add, nested in `SessionsSidebarStructure`:

```swift
/// Where jump-to-attention lands: the row to highlight and the agent's own surface.
struct AttentionTarget: Equatable, Sendable {
  var rowID: SessionRowID
  var location: SessionLocation   // layoutID (task), tabID, surfaceID
}
```

Delete `nextNeedingAttention(from:items:)` (one caller). Add to the existing
`extension RepositoriesFeature.State` in the same file (needs the private `members(of:agents:)`):

```swift
func nextAttentionTarget(after current: SessionRowID?, focusedSurfaceID: UUID?) -> SessionsSidebarStructure.AttentionTarget?
```

Rules:
- An agent *qualifies* iff `allowsAttentionNavigation && (status == .needsYou || status == .doneUnseen)`.
  Same test as today, applied per agent for task rows, per row for the others.
- Walk order = `sessionsSidebarStructure.liveIDs` order; inside a `.task` row, its agents in member order.
- A position is `(rowIndex, agentIndex)`. Pick the first candidate strictly greater than the cursor
  (lexicographic); if none, the first candidate overall (wrap; may be the cursor's own surface, as today).

Pseudocode:

```swift
let live = sessionsSidebarStructure.liveIDs
guard !live.isEmpty else { return nil }
// one pass; keeps sessionSnapshots' order inside each bucket
var agentsByTask: [LayoutID: [SessionLiveSnapshot]] = [:]
for agent in sessionSnapshots { agentsByTask[agent.location.layoutID, default: []].append(agent) }

func orderedAgents(_ layoutID: LayoutID) -> [SessionLiveSnapshot] {
  let agents = agentsByTask[layoutID] ?? []
  guard agents.count > 1 else { return agents }
  var rank: [TaskMember: Int] = [:]
  for (i, m) in members(of: layoutID, agents: agents).enumerated() where rank[m] == nil { rank[m] = i }
  // stable: equal members keep snapshot (surface) order
  return agents.enumerated().sorted {
    (rank[$0.element.member] ?? .max, $0.offset) < (rank[$1.element.member] ?? .max, $1.offset)
  }.map(\.element)
}

var candidates: [(row: Int, agent: Int, target: AttentionTarget)] = []
var cursor: (row: Int, agent: Int)? = nil
for (rowIndex, id) in live.enumerated() {
  if case .task(let layoutID) = id {
    let agents = orderedAgents(layoutID)
    if id == current {
      // last match: two harnesses on one surface count as one stop. -1 = not on an agent (shell tab / unknown)
      cursor = (rowIndex, focusedSurfaceID.flatMap { s in agents.lastIndex { $0.location.surfaceID == s } } ?? -1)
    }
    for (i, agent) in agents.enumerated() where qualifies(agent) {
      candidates.append((rowIndex, i, .init(rowID: id, location: agent.location)))
    }
  } else {
    if id == current { cursor = (rowIndex, 0) }
    guard let item = sessionItems[id: id], item.allowsAttentionNavigation, let location = item.location,
      item.status == .needsYou || item.status == .doneUnseen else { continue }
    candidates.append((rowIndex, 0, .init(rowID: id, location: location)))
  }
}
guard let cursor else { return candidates.first?.target }   // current nil or not live: from the top
return (candidates.first { ($0.row, $0.agent) > cursor } ?? candidates.first)?.target
```

Notes for the implementer:
- `.implicit`/`.provisional` rows keep reading the **row** (`sessionItems[id:]`), exactly as today: one agent
  per row, and existing tests build such rows without snapshots. Only `.task` rows expand into agents.
- Do not read a task row's `status`/`location` here at all.
- Line-of-sight: extract `orderedAgents` and `qualifies` as private helpers; keep the function body flat.
- Cost per press: O(agents + live rows + members of tasks that hold >1 agent). Runs only on the chord.

### 2.2 `AppFeature+Sessions.swift` — `handleNextSessionNeedsMe`

```swift
static func handleNextSessionNeedsMe(state: inout State) -> Effect<Action> {
  let focusedRow = focusedSessionRowID(state: state)
  let target = state.repositories.nextAttentionTarget(
    after: focusedRow ?? state.repositories.sessionSelection,
    // A surface only means something against the row it was read with.
    focusedSurfaceID: focusedRow == nil ? nil : focusedSurfaceID(state: state))
  guard let target, hasTask(target.location.layoutID, state: state) else { return .none }
  state.repositories.selectSessionRow(target.rowID)
  return .send(.repositories(.delegate(.focusSession(target.location))))
}
```

No other source change. `focusSession` already selects the target's task and focuses the surface.
Menu item, shortcut, tooltip and `FocusedAction` publishing are unchanged.

## 3. Destructive and persistence paths

None. The slice sends exactly one effect, `focusSession`, which yields `selectTask` + `focusSurface`.
Rules to hold:
- Never send `createTab`, `createTabWithInput`, `ensureInitialTab`, `resumeSession`, `unsettleSession`,
  `settle*`, or any close/destroy command from this path. A dormant member is never a candidate (candidates
  come from live snapshots / rows with a `location` only).
- No write to `taskSessions`, `terminals.members`, the sidecar or the layouts file. Member order is read, never
  re-sorted in state (the sort in `orderedAgents` is on a local copy).
- No timer, no remembered "last jump" state: every press decides from the state at that instant.
- `hasTask` guard: do not select or focus a layout that no longer exists (a `focusSurface` on it would build
  a host for a removed task).

## 4. Edge cases and required behaviour

| Case | Required |
|---|---|
| Leader working/error, tangent done-unseen or awaiting input | Tangent is the target; row highlighted is its task. |
| Two qualifying agents in one task, focus on a shell tab of that task (cursor agent −1) | First in member order (own task first). |
| …focus on the first of them (still qualifying) | The second; then the next rows; wraps back. |
| Focus on the last qualifying agent of a task | Next live row's first candidate, not the same task again. |
| Only the focused agent qualifies | Returns it (re-focus; harmless), as today. |
| Nothing qualifies; error-only; working-only | `nil`, no selection change, no effect. |
| Selection on a dormant/settled row not in `liveIDs`, nothing focused | Start from the top of `liveIDs`. |
| Unlisted agent (reported, not yet in `taskSessions`) | Ordered after listed members, by surface. |
| Two agents share one `TaskMember` (same session on two surfaces) | Both are stops, in surface order. |
| Session listed by two tasks | A target only in the task whose surface it runs on (bucketed by `location.layoutID`). |
| Agent on a surface no known task holds (`.implicit`/`.provisional` row) | Row path, as today. |
| Agent's layout has no `.task` row in `liveIDs` (snapshot ahead of reconcile) | Not a candidate this press. |
| Second press before the first focus lands (key repeat; cursor still the old surface) | Same target again; idempotent; no extra commands beyond select+focus. |
| Presence flips between presses (visited target cleared by focus) | It is no longer a candidate; cursor math still works since the cursor index is over *all* agents, not only candidates. |
| Target's task removed between snapshot and press | `hasTask` false → no-op. Not "try the next one": the next `.terminals` pass refreshes snapshots. |
| Target's tab closed, task remains | `focusSession` runs; the manager logs and focuses nothing; the task is shown. Accepted (one-hop window). |
| Target in an orphan task (directory not in roster) | Works: `focusSession` → `selectTask` orphan branch. |
| Settled-but-live `.implicit` row | Still jumped to, not unsettled (unchanged). |
| Hibernated target surface | `focusSurface` wakes the tab (existing); no resume/mint. |

## 8. Decisions the plan left open, and deviations

- **Computed on press, not cached.** Plan names `nextNeedingAttention` on the structure; this moves the pick
  to a `RepositoriesFeature.State` method reading `sessionSnapshots`. Reason: a cached target list changes on
  every status flip and would add structure writes (A26) for something read once per key press.
- **Return type** is `AttentionTarget { rowID, location }`, not a bare `(task, tab, surface)` tuple: the
  location already carries layout, tab and surface, and non-task rows need their row id for the highlight.
- **Order is list order, circular**, not urgency order (needs-you before done-unseen). Unchanged from today;
  D7's urgency ranking is about the row badge only.
- **Own task first** when focus is on a non-agent tab of a task; after an agent, later members of the same
  task come before other tasks. Reason: matches sub-row order and makes every stop reachable in one lap.
- **Cursor is the focused surface from current state**, no stored "last target". A press that outruns the
  focus round-trip repeats its target instead of skipping one. Reason: stateless, cannot drift; cost is at
  most one absorbed key repeat.
- **`hasTask` guard is a no-op, not a skip-to-next.** Simpler, non-destructive, self-heals on the next pass.
- **`.error` stays non-jumpable** and jump never unsettles or resumes: unchanged behaviour, not revisited.
- **Hybrid source** (snapshots for task rows, row state for `.implicit`/`.provisional`): keeps the existing
  tests and the one-agent-per-row path byte-for-byte; no contradiction with D1–D12 or any Decided entry.
- Nothing here contradicts the plan beyond the function's home and name (first bullet).
