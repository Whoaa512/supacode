## 2. Design

### 2.1 Pure membership (`Domain/TaskRecord.swift`, in `TaskMembership`)

```swift
/// What a tab transfer does to the two tasks' members.
enum Transfer: Equatable, Sendable {
  case none                              // M2's plain move; kept for M2's tests
  case merge                             // all of `from`'s members follow, in order
  case detach(surfaceID: UUID, sessions: [SessionKey])  // the sessions running on the moved tab
}

/// destination first, exactly as it was; then source's members in source
/// order, skipping any destination already lists. Use a Set for the check.
static func merging(_ source: [TaskMember], into destination: [TaskMember]) -> [TaskMember]

struct Detachment: Equatable { var kept: [TaskMember]; var moved: [TaskMember] }
/// moved = members that are `.session(k)` with k in `sessions`, or
/// `.provisional(_, surfaceID)`, in member order; then `.session(k)` for any
/// k in `sessions` the list lacks, in the given order. kept = the rest, order
/// unchanged. nil when `members.first` would move (the primary).
static func detaching(surfaceID: UUID, sessions: [SessionKey], from members: [TaskMember]) -> Detachment?
```

No `TaskRecord` field is added (A30: still no parent/child).

### 2.2 `TerminalsFeature` (`Features/Terminal/Reducer/TerminalsFeature.swift`)

- New state `var storedLayoutsLoaded = false`, set `true` at the end of
  `.layoutsHydrated`. (Existing exhaustive tests that send `.layoutsHydrated`
  gain one asserted line.)
- M2's action gains one associated value:
  `.transferTabs(from:to:tabs:membership: TaskMembership.Transfer = .none)`.
  The case becomes: (1) when `membership != .none`, return `.none` with no
  change unless the matching refusal function below returns nil (for
  `.detach` that includes `TaskMembership.detaching(...) != nil`); (2) M2's
  layout mutation; (3) the membership move:

```swift
switch membership {
case .none: break
case .merge:
  let merged = TaskMembership.merging(state.members[from] ?? [], into: state.members[to] ?? [])
  state.members[to] = merged.isEmpty ? nil : merged
  state.members[from] = nil
case .detach(let surfaceID, let sessions):
  // non-nil: step 1 already checked it
  let split = TaskMembership.detaching(surfaceID: surfaceID, sessions: sessions, from: state.members[from] ?? [])!
  state.members[from] = split.kept.isEmpty ? nil : split.kept
  state.members[to] = split.moved.isEmpty ? nil : split.moved
}
```

  Layouts and members never change apart. No `sessionsChanged` effect: the
  manager flushes (§3). Prefer `guard let` over the `!` in real code.
- Refusals, one pure function each on `TerminalsFeature.State`:

```swift
enum TransferRefusal: Equatable, Sendable {
  case sameTask, storeNotReady, unknownTask, targetHasNoTab, differentHost,
       closePending, scriptRunning, launchPending, noSuchTab, primaryTab, onlyTab
}
func mergeRefusal(_ source: LayoutID, into target: LayoutID) -> TransferRefusal?
func detachRefusal(tab: TabID, from source: LayoutID, sessions: [SessionKey]) -> TransferRefusal?
```

  `mergeRefusal`, first match wins:
  1. `source == target` → `.sameTask`
  2. `!storedLayoutsLoaded || storedSessions != .loaded || layoutsAreReadOnly` → `.storeNotReady`
  3. `layouts[id: source] == nil || layouts[id: target] == nil || directories[source] == nil || directories[target] == nil` → `.unknownTask`
  4. target holds no tab → `.targetHasNoTab`
  5. `directories[source]!.host != directories[target]!.host` → `.differentHost`
  6. either layout's `alert != nil` → `.closePending`
  7. source holds a tab with `isLocked` → `.scriptRunning`

  `detachRefusal`: rule 2; source layout or directory unknown → `.unknownTask`;
  tab not in source → `.noSuchTab`; source `alert != nil` → `.closePending`;
  tab `isLocked` → `.scriptRunning`;
  `TaskMembership.detaching(...) == nil` → `.primaryTab`; source holds exactly
  one tab and `kept` has no `.session` → `.onlyTab` (nothing would be left).

### 2.3 `AppFeature` (`AppFeature.swift` action enum, logic in `AppFeature+Sessions.swift`)

New actions: `.mergeTask(LayoutID, into: LayoutID)`, `.detachTab(LayoutID, tabID: TabID)`,
`.detachFocusedTab`, `.taskMergeFinished(source: LayoutID, target: LayoutID)`,
`.taskDetachFinished(new: LayoutID, directoryID: Worktree.ID)`.

Statics (callable from the manager through `appStore.withState`):

```swift
/// Valid sessions presence reports on a surface now, by harness raw value.
static func sessions(onSurface surfaceID: UUID, state: State) -> [SessionKey]
static func mergeRefusal(_ a: LayoutID, into b: LayoutID, state: State) -> TerminalsFeature.TransferRefusal? {
  if let r = state.terminals.mergeRefusal(a, into: b) { return r }
  return state.pendingTaskLaunches.contains { $0.layoutID == a } ? .launchPending : nil
}
static func detachRefusal(_ s: LayoutID, tabID: TabID, state: State) -> TerminalsFeature.TransferRefusal?
  // surfaceID from the tab; sessions(onSurface:); state.terminals.detachRefusal(...)
```

Handlers:

- `.mergeTask(a, into: b)`: refusal → `.send(.repositories(.showToast(.info(text))))`,
  nothing else. Else build B's context with
  `directoryContext(forTask: b, directoryID: state.terminals.directories[b]!.worktreeID, state:)`
  and return `.run { await terminalClient.send(.mergeTask(a, into: b, context)); await send(.taskMergeFinished(source: a, target: b)) }`.
- `.taskMergeFinished(a, b)`: if `hasTask(a, state:)` is still true → toast
  "Couldn't merge the task." and stop. Else `focusTask(b, directoryID:, state:)`
  (selects B; `ensureInitialTab` cannot bootstrap because B holds tabs).
- `.detachTab(s, tabID)`: refusal → toast. Else mint `let new = LayoutID(task: uuid())`
  (`@Dependency(\.uuid)`), context = S's (`directoryContext(forTask: s, …)`, so
  the new task sits on S's directory and host), return
  `.run { await terminalClient.send(.detachTab(from: s, tabID: tabID, to: new, context)); await send(.taskDetachFinished(new: new, directoryID: context.worktreeID)) }`.
- `.taskDetachFinished(new, directoryID)`: only when
  `state.terminals.layouts[id: new]` holds a tab → `focusTask(new, directoryID:, state:)`;
  otherwise toast "Couldn't detach the tab." and select nothing. Never send
  `.selectTask` for a task that holds no tab (it would bootstrap a shell).
- `.detachFocusedTab`: layout = `state.terminals.selectedLayoutID`, tab = its
  focused pane's `selectedTabID` (same walk as `focusedSurfaceID`); missing →
  toast; else `.send(.detachTab(layout, tabID: tab))`.
- Wiring: `.repositories(.delegate(.mergeTask(a, into: b)))`,
  `.repositories(.delegate(.detachTab(s, tabID:)))`,
  `.commandPalette(.delegate(.mergeTask…))`, `.commandPalette(.delegate(.detachFocusedTab))`
  each forward to the actions above.

Toast text by refusal: `.primaryTab` "The primary session can't be detached.
Merge the other way instead."; `.onlyTab` "This is the task's only tab.";
`.differentHost` "Tasks on different hosts can't be merged."; `.closePending`
"Answer the close confirmation first."; `.scriptRunning` "Wait for the running
script to finish."; `.launchPending` "A session is still starting in this
task."; `.storeNotReady` "Tasks are still loading."; the rest "That task is no
longer available."

### 2.4 `TerminalClient` and manager

`TerminalClient.Command` (add to every exhaustive switch the compiler names):

```swift
case mergeTask(LayoutID, into: LayoutID, DirectoryContext)                // target's context
case detachTab(from: LayoutID, tabID: TabID, to: LayoutID, DirectoryContext)
```

`WorktreeTerminalManager` (called from `handleCommand`):

```swift
func mergeTask(_ a: LayoutID, into b: LayoutID, context: DirectoryContext) {
  guard let appStore, appStore.withState({ AppFeature.mergeRefusal(a, into: b, state: $0) }) == nil else { log; return }
  guard transferTabs(from: a, to: b, tabs: nil, destination: context, membership: .merge) else { return }
  // contract item 5: A's host and layout are gone here; do it now if M2 did not
  flushTransfer(records: [b], deleting: a)
}

func detachTab(from s: LayoutID, tabID: TabID, to new: LayoutID, context: DirectoryContext) {
  guard let appStore, hosts[new] == nil, layoutState(for: new) == nil else { return }
  let facts = appStore.withState { state -> (UUID, [SessionKey])? in
    guard AppFeature.detachRefusal(s, tabID: tabID, state: state) == nil, let surfaceID = /* tab's content id */ else { return nil }
    return (surfaceID, AppFeature.sessions(onSurface: surfaceID, state: state))
  }
  guard let (surfaceID, sessions) = facts else { log; return }
  guard transferTabs(from: s, to: new, tabs: [tabID], destination: context,
                     membership: .detach(surfaceID: surfaceID, sessions: sessions)) else { return }
  flushTransfer(records: [s, new], dropping: [s: sessions])
}
```

The check, the session read and the reducer action run in one synchronous
main-actor stretch, so nothing can change between deciding and moving.
M2's primitive forwards `membership` into its reducer action.

## 3. Destructive and persistence paths

Rules: decide on current, positively identified state; never reorder; never on a timer.

1. **A's record is deleted only in the same flush that stores its tabs and
   sessions in B.** New manager function:

```swift
private func flushTransfer(records ids: [LayoutID], deleting deleted: LayoutID? = nil,
                           dropping: [LayoutID: [SessionKey]] = [:])
```

   - `guard layoutsAreReadOnly != true` (as the other flushes).
   - For every id in `ids` and `deleted`: cancel and clear `layoutDirtyTasks[id]`;
     collect `layoutFlushTasks[id]?.task`.
   - Build each `.record` now from the post-transfer state with
     `recordChange(for:layout:)` over `LayoutPersistence.record(...)` (as
     `flushLayoutSnapshot` does); for an id in `dropping`, pass its list as the
     new `dropping:` value.
   - One `Task`: await every collected in-flight task, then **one**
     `writer.flush(records: [b: .record…, a: .delete])` (or `[s: …, new: …]`).
     Register the task under every involved key in `layoutFlushTasks` with a
     fresh generation, cleared generation-gated as today.
   - Never two flushes, never the delete first: a crash between them would
     either leave the tabs in two records (hydration then drops one whole
     record on an id collision) or in none (the orphan reaper kills their zmx
     sessions).
2. **`RecordChange.record` gains `dropping: [SessionKey] = []`**
   (`LayoutsIncrementalWriter.swift`). In `apply`, after `TaskMembership.storing`:
   `task.sessions.removeAll { dropping.contains($0) }`, before the "no tab and
   no session" check. Only `flushTransfer` for a detach passes it, and only
   with sessions the same flush stores in the new task's record: a session is
   moved between records, never dropped from the store.
3. **Merge never deletes a record it has not positively loaded**: `.unknownTask`
   when A has no entry in `layouts` (its record was refused at hydration as
   inconsistent or colliding, so its tabs exist only in the store). Deleting
   there would release live zmx sessions to the reaper.
4. **Order.** B's members after merge are B's list untouched, then A's in A's
   order (primary of A first among the tangents). The store gets that order
   through `storing(.loaded)` (run's order stands). Detach keeps the relative
   order on both sides. Hydration after a relaunch replays onto that stored
   order, so whichever agent reports first changes nothing.
5. **No close, kill or settle.** M3 sends no `closeTab`, `destroyTab`,
   `closeAllTabsRequested`, `settleSession` or `settleTask`, marks no
   user-close intent and touches no sidecar entry. A's primary keeps whatever
   settle mark it had and becomes a tangent with it. Presence records are not
   touched (they are keyed by surface, which does not change).
6. **Not ready, not done.** Before `.layoutsHydrated`, with stored sessions
   not `.loaded`, or with a read-only file, both operations refuse. The
   launch-time hydration would otherwise re-add A's stored sessions under a
   task that no longer exists, or re-add a detached session to its old task
   and write that back.
7. **Hosts.** Tasks whose `TaskRecord.Directory.host` differ never merge: the
   destination host's context decides where a tab's session is killed and
   re-attached, so a remote tab under a local task would leak its host session
   on close and fail to wake. A detached task copies the source's directory and
   host.
8. `activeTasks`: the writer's `.delete` already clears entries naming A;
   `.detachLayout` clears the runtime map. Origins are released only with a
   directory's last task and A's surface ids now sit in B's record, so
   `allKnownSurfaceIDs` is unchanged by a merge (assert it).

## 4. Edge cases and races

| Case | Required behaviour |
|---|---|
| Agents of A report in surface-uuid order that differs from A's member order | B's list is B + A in A's order; the reconcile that follows the transfer pass changes nothing |
| A has a provisional member | It moves into B's list in place; when its ref arrives it becomes a session in that slot |
| A and B both list a session | Listed once in B, at B's position |
| A has no tabs (dormant, sessions only) | Same path; nothing to move; sessions appended, record deleted |
| A is shell-only | Tabs move, no members change, record deleted |
| A is selected, or neither is | A's selection ends through the existing `.selectedTaskRemoved`; B is selected and focused |
| Merge of a merged task (A→B, then B→C) | C lists C, B's, A's sessions flat; one layout; records A and B gone |
| A positive flush of A is in flight or debounced | Debounce cancelled; in-flight awaited before the one transfer flush; A's record does not come back |
| `handleLayoutChanged(A)` arrives after the merge (observer effect) | No-op: no host, no layout; nothing written, nothing torn down |
| Close confirmation pending on A or B | Refused (`.closePending`); the confirmation names tabs of a layout that would change |
| A holds a running blocking-script tab; detach of one | Refused (`.scriptRunning`) |
| A launch into A whose tab has not appeared (`pendingTaskLaunches`) | Refused (`.launchPending`). Cost: an entry whose tab never appears blocks merging that task for the run (T7 r2 keeps such entries) |
| Stale request (menu opened, task closed meanwhile) | Refusal toast; nothing changes |
| M2 refuses at runtime | `taskMergeFinished` sees A still there: toast, no selection change. `taskDetachFinished` sees no tab in the new id: toast, no `.selectTask` |
| Detach of the tab the primary runs on, or of a first member that is provisional on that surface | Refused (`.primaryTab`) |
| Detach of a tab left by an ended primary (no agent on it) | Allowed: it is a plain shell tab now; new task is shell-only |
| Detach of the only tab of a task that would list no session | Refused (`.onlyTab`) |
| Detach of the only tab of a task that keeps a session (dormant primary) | Allowed; source keeps its empty layout, host and record (existing "task with sessions" rule; `removeTaskIfEmptied` keeps it because `members` lists a session) |
| Session replaced by `/new` on the detached tab (dormant, settled member) | Stays in the source: nothing positively ties it to the tab |
| Agent on the detached tab reports its ref between the menu and the command | The manager reads presence in the same stretch as the move, so the session moves with the tab and is not listed twice |
| Session also listed by a third task | That task is untouched |
| New task id already exists | Manager returns without change |
| Sub-rows after detach | Source may drop to one member: `subRows` empties (existing rule); new task row appears and is selected |
| Detached tab runs in another directory (D9) | New task still sits on the source's directory |

## 8. Decisions the plan left open, and contradictions

Decisions (each is the non-destructive or simplest side; cj to veto):

1. **Membership moves inside M2's reducer action**, not in a second action:
   otherwise the reconcile between them re-lists A's sessions under B in
   surface order. This adds a parameter to M2's action and primitive.
2. **One flush for both records**, and a `dropping` list on the writer for
   detach (T7's "M needs its own remove change").
3. **Refusals** not in the plan: store not ready (before hydration,
   unreadable, read-only), source record not loaded as a layout, different
   hosts, pending close confirmation, running blocking script, launch pending
   into the source, detaching a task's only tab when no session would be left.
4. **"The primary's tab" is the tab the primary runs on now.** A tab left by
   an ended primary detaches as a shell tab.
5. **Sessions that move on detach are those presence reports on the tab**
   (plus provisional members on its surface). Earlier sessions replaced on that
   tab stay with the source.
6. **Detached task**: source's directory and host, new `LayoutID(task:)`,
   selected and focused after the move. (Plan says "select B" for merge and
   nothing for detach; alternative is to stay on the source.)
7. **Merge source may be dormant** (sessions only); target must hold a tab.
   `.implicit` rows are neither source nor target: there is no record to merge.
8. **Detach on a dormant sub-row is not offered**: there is no tab to move.
9. **Merge targets ride on `SessionsSidebarStructure`** so the menu reads no
   `sessionItems[id:]` in a body.
10. New `TerminalsFeature.State.storedLayoutsLoaded`. Cost: a line in existing
    exhaustive hydration tests.

Contradictions and gaps against the plan:

- The plan's file list for M3 omits `TerminalsFeature.swift`, `TaskRecord.swift`,
  `LayoutsIncrementalWriter.swift`, `WorktreeTerminalManager.swift`,
  `TerminalClient.swift`, `SessionsSidebarStructure.swift` and
  `CommandPaletteItem.swift`; all are needed.
- "Detach on a sub-row" cannot reach a plain shell tab (sub-rows are agents
  only, and a task with one agent has none), yet A29 requires it. The palette's
  "Detach Tab into New Task" on the focused tab is the entry point for that.
- M2 as written names only `transferTabs(from:to:)`. Detach needs one tab moved
  into a task that does not exist yet, and merge needs the membership payload;
  §0 states both as M2's contract.
- "A's record is removed" needs an explicit `.delete`: the writer keeps any
  record that lists a session, so without it A returns as a dormant task.
- No conflict with D8, Q8 (primary refused) or Q9 (menu and palette only).
