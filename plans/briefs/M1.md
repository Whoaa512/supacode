## 1. What exists today (build on these, change none of them)

`supacode/Features/Terminal/Models/PaneLayout.swift`
- `PaneLayout { tree: SplitTree<PaneID>, panes: IdentifiedArrayOf<Pane>, focusedPaneID }`.
  The memberwise `init` repairs a dangling `focusedPaneID` to `panes.first?.id`.
- `Pane { id, tabs: IdentifiedArrayOf<TabItem>, selectedTabID }`; `init`
  repairs a dangling selection to `tabs.first?.id`.
- `TabItem { id: TabID, title, customTitle, icon, tintColor, content: ContentSnapshot, isLocked }`.
  **A tab hosts exactly one content.** `isLocked` and
  `TerminalContentState.launch` are live-only: Codable drops them.
- `ContentSnapshot { id: ContentID, state }`. A surface id is
  `ContentID.rawValue` (see `WorktreeContentHost`: `ContentID(rawValue: surfaceID)`),
  so "surface id preserved" == "content id preserved".
- `PaneLayout.isConsistent`: tree leaves == panes one-to-one, no empty pane,
  selections resolve, focus exists iff panes do, tab ids and content ids
  unique. An empty layout (`PaneLayout()`) is consistent.
- `PaneLayout.pane(containingTab:)`, `allContentIDs`.

`supacode/Features/Terminal/Models/SplitTree.swift`
- `leaves()` (depth-first, left before right = visual order),
  `find(id:)` (takes `PaneID.rawValue`), `removing(_:)` (clears `zoomed` when
  the removed node is the zoomed one), `focusTargetAfterClosing(_:)`,
  `init(view:)`, `inserting(view:at:direction:)`.

`supacode/Features/Terminal/Reducer/LayoutFeature.swift` (reference behaviour
to mirror, not to call; these are private and state-bound)
- `reduceCloseTab`: selection retargets to the previous tab, else the first.
- `collapse(_:paneID:)`: compute `focusTargetAfterClosing` **before** removing
  the leaf; remove leaf and pane; refocus only if the removed pane held focus,
  to the computed target if it still exists, else `panes.first`, else nil.
  It also clears `windowedPaneIDs`, `alert`/`alertPaneID` and calls
  `equalizeIfEnabled` (reads `@Shared(.settingsFile)`): state-side work M1
  does not do (see 2.5).

`supacode/Features/Terminal/BusinessLogic/LayoutsTaskSplitter.swift`
- Private `singlePaneLayout(_:paneID:)` and the "fresh pane id for a moved
  tab, tab/content ids never change" precedent (T1 Progress). Do not edit the
  splitter (migration code); M1 writes its own 5-line equivalent.
- `TerminalRestorePruner.prunedLayout` is the precedent for removing a pane's
  leaf from the tree in pure code.

`supacode/Domain/TaskRecord.swift`: `TaskRecord.layout` may be empty ("a task
whose tabs are all closed"), so both operations must accept an empty layout.

## 2. Design

### 2.1 File and type

New `supacode/Features/Terminal/BusinessLogic/LayoutTransfer.swift`:

```swift
import Foundation
import IdentifiedCollections

/// Moves tabs between task layouts. Pure: never drops or re-identifies a tab
/// or its content.
nonisolated enum LayoutTransfer {
  enum Failure: Error, Equatable {
    case inconsistentSource
    case inconsistentDestination
    /// A tab id or content id appears on both sides.
    case duplicateIdentity
    case tabNotFound
  }

  struct Flattened: Equatable {
    /// The destination after the move.
    var layout: PaneLayout
    /// The pane the tabs landed in; nil only when both layouts are empty.
    var targetPaneID: PaneID?
    /// True when the destination was empty and `targetPaneID` is new.
    var createdPane: Bool
    /// Moved tabs in landing order.
    var movedTabIDs: [TabID]
    /// The tab the source was showing (its focused pane's selection).
    var sourceActiveTabID: TabID?
  }

  struct Extraction: Equatable {
    /// One new pane holding only the tab.
    var extracted: PaneLayout
    /// The source without the tab; empty when it was the last one.
    var remainder: PaneLayout
    /// The source pane the move emptied and removed, if any.
    var collapsedPaneID: PaneID?
  }

  static func flatten(
    _ source: PaneLayout,
    into destination: PaneLayout,
    makePaneID: () -> PaneID = { PaneID() }
  ) throws -> Flattened

  static func extract(
    _ tabID: TabID,
    from source: PaneLayout,
    makePaneID: () -> PaneID = { PaneID() }
  ) throws -> Extraction
}
```

No free functions (AGENTS.md). No `@Shared`, no `@Dependency`, no logging:
the functions take values and return values. `makePaneID` is injected for
tests, as `makeUUID` is in `LayoutsTaskSplitter.split`.

### 2.2 `flatten` pseudocode

```
guard source.isConsistent      else throw .inconsistentSource
guard destination.isConsistent else throw .inconsistentDestination

ordered = source.tree.leaves()                 // visual order, see 2.3
            .compactMap { source.panes[id: $0] }
            .flatMap { Array($0.tabs) }        // strip order inside each pane

// IdentifiedArray.append silently ignores a duplicate id: check first.
destTabIDs     = Set(destination.panes.flatMap { $0.tabs.ids })
destContentIDs = Set(destination.allContentIDs)
guard ordered.allSatisfy({ !destTabIDs.contains($0.id) && !destContentIDs.contains($0.content.id) })
  else throw .duplicateIdentity

active = source.focusedPaneID.flatMap { source.panes[id: $0]?.selectedTabID }
moved  = ordered.map(\.id)

// Case 1: destination has panes (consistent => focusedPaneID resolves).
if let focused = destination.focusedPaneID, var pane = destination.panes[id: focused]:
  for tab in ordered { pane.tabs.append(tab) }       // after the existing tabs
  var result = destination
  result.panes[id: focused] = pane                   // selection, focus, tree, zoom untouched
  return Flattened(layout: result, targetPaneID: focused, createdPane: false,
                   movedTabIDs: moved, sourceActiveTabID: active)

// Case 2: both empty. No pane is invented.
if ordered.isEmpty:
  return Flattened(layout: destination, targetPaneID: nil, createdPane: false,
                   movedTabIDs: [], sourceActiveTabID: nil)

// Case 3: empty destination, tabs to move.
id = makePaneID()                                    // the only call
layout = PaneLayout(tree: SplitTree(view: id),
                    panes: [Pane(id: id, tabs: IdentifiedArray(uniqueElements: ordered),
                                 selectedTabID: active)],   // Pane.init falls back to first
                    focusedPaneID: id)
return Flattened(layout: layout, targetPaneID: id, createdPane: true,
                 movedTabIDs: moved, sourceActiveTabID: active)
```

`makePaneID` is called only in case 3. Postcondition (debug `assert`, and
tested): `result.layout.isConsistent`.

The source value is not returned: flatten consumes all of it. The caller
(M3) deletes A's record; M1 never represents "A emptied".

### 2.3 Order rule (fixed)

Source tabs land in **tree leaf order** (`tree.leaves()`), then strip order
within each pane, after all tabs the target pane already had. Not
`source.panes` order: that array is creation history (`reduceMoveTabToSplit`
appends), so it does not match what the user sees. Leaf order is what
`WorktreeTerminalManager.focusRelativePane` already calls "visual tree order".

### 2.4 `extract` pseudocode

```
guard source.isConsistent else throw .inconsistentSource
guard var pane = source.pane(containingTab: tabID),
      let index = pane.tabs.index(id: tabID) else throw .tabNotFound
let tab = pane.tabs[index]                       // the value, untouched

newID = makePaneID()                             // exactly once
extracted = PaneLayout(tree: SplitTree(view: newID),
                       panes: [Pane(id: newID, tabs: [tab], selectedTabID: tab.id)],
                       focusedPaneID: newID)

var remainder = source
pane.tabs.remove(at: index)
if !pane.tabs.isEmpty:
  if pane.selectedTabID == tabID:
    pane.selectedTabID = index > 0 ? pane.tabs[index - 1].id : pane.tabs.first?.id
  remainder.panes[id: pane.id] = pane
  return Extraction(extracted, remainder, collapsedPaneID: nil)

// the move emptied the pane: same rule as LayoutFeature.collapse
node   = remainder.tree.find(id: pane.id.rawValue)       // non-nil: source is consistent
target = node.flatMap { remainder.tree.focusTargetAfterClosing($0) }   // BEFORE removal
if let node { remainder.tree = remainder.tree.removing(node) }
remainder.panes.remove(id: pane.id)
if remainder.focusedPaneID == pane.id:
  remainder.focusedPaneID =
    target.flatMap { remainder.panes[id: $0] != nil ? $0 : nil } ?? remainder.panes.first?.id
return Extraction(extracted, remainder, collapsedPaneID: pane.id)
```

Postconditions (assert + tested): `extracted.isConsistent`,
`remainder.isConsistent`, and tab ids / content ids of `extracted` +
`remainder` equal the source's as multisets.

The extracted pane always gets a fresh id (never the source pane's), so two
layouts never share a pane id; pane windows and focus are keyed by pane id.

### 2.5 What M1 deliberately leaves to the caller (write these in the doc comments)

- `LayoutFeature.State` bookkeeping: on `collapsedPaneID` drop it from
  `windowedPaneIDs`, clear `alert`/`alertPaneID` if it owned the alert, clear
  `editingTabID` if it is the extracted tab, and apply `equalizeIfEnabled`.
  For flatten, the same for every pane of the source state. (M2.)
- Showing the moved tab: M1 keeps the destination's selection. M3 may send
  `.selectTab(id: sourceActiveTabID)` after the merge if it wants A's tab shown.
- Sessions: which `SessionKey`s ride with a tab (`TerminalContentState.agents`),
  primary refusal on detach (Q8), record deletion. (M3.)
- Refusing while a tab is a locked blocking-script runner
  (`TabItem.isLocked` / `ContentState.isEphemeral`). M1 moves such a tab
  unchanged like any other.

## 3. Destructive and persistence paths

M1 writes nothing and kills nothing. The rules it must satisfy so M2/M3 can
build destructive steps on it:

- **Nothing is dropped.** For every success: multiset of `(TabID, ContentID)`
  out == in. A dropped tab is a zmx session nobody owns once M3 deletes A's
  record. Hence the explicit duplicate check instead of trusting
  `IdentifiedArray.append` (which returns `inserted: false` and moves on).
- **Nothing is re-identified or rebuilt.** Move the `TabItem` value itself.
  Never construct a new `TabItem`/`ContentSnapshot`, never round-trip through
  Codable: that would strip `isLocked`, `launch`, and would be invisible in an
  ids-only test.
- **Refuse rather than repair.** Inconsistent input or an identity collision
  throws and returns nothing; no partial result. The caller must leave both
  tasks untouched on a throw.
- **Order is exact.** Destination's existing tabs keep their order and
  indices; moved tabs follow in the 2.3 order; `movedTabIDs` is that same
  order. The order survives a `PaneLayout` encode/decode (`Pane.encode`
  writes `Array(tabs)`); tested.
- **Decide on current state.** Both functions are synchronous over the values
  passed in. Callers must read both layouts and apply the result in one
  reducer turn; never compute in one action and apply after an effect.
- No timer, no close, no kill, no tombstone anywhere in this slice.

## 4. Edge cases and required behaviour

| Case | Required |
|---|---|
| A has several panes (splits) | All tabs land in B's focused pane, leaf order; A's tree is discarded (sizing "Open": flattened). |
| A empty, B non-empty | Success; `layout == destination`, `movedTabIDs == []`. |
| A non-empty, B empty | One new pane, selection = A's active tab, `createdPane == true`. |
| A empty, B empty | Success; `layout == PaneLayout()`, `targetPaneID == nil`, `makePaneID` not called. |
| A == B (same value), or any shared tab/content id | `throw .duplicateIdentity`. |
| A or B fails `isConsistent` | `throw .inconsistentSource` / `.inconsistentDestination`. |
| B zoomed | Zoom untouched (tree identical). |
| A zoomed | Zoom discarded with A's tree. |
| B's focused pane is shown in a pane window | Tabs still land there (it is the focused pane); M2 owns the window. |
| A holds hibernated tabs (`frozenGrid`) or locked tabs | Moved as values, fields intact. |
| extract: tab not in layout | `throw .tabNotFound`. |
| extract: selected tab, others remain | Selection → previous tab, else first; focus unchanged; `collapsedPaneID == nil`. |
| extract: non-selected tab | Selection unchanged. |
| extract: only tab of a non-focused pane | Pane and leaf removed; focus unchanged. |
| extract: only tab of the focused pane | Focus → `focusTargetAfterClosing` result (next if leftmost, else previous). |
| extract: only tab of the zoomed pane | `remainder.tree.zoomed == nil`. |
| extract: last tab of the layout | `remainder == PaneLayout()` (empty tree, no focus), `collapsedPaneID` set. Whether that is allowed is M3's call (Q4: shell-only task with no tab is deleted). |
| flatten(extract(t).extracted, into: remainder) | Consistent; same id multiset as the original (round trip). |

Races: none inside M1 (pure). The only hazard is a caller holding a result
across a suspension; see section 3.

## 8. Decisions taken, and conflicts with the plan

Conflicts
- **"Splits inside a tab kept" (plan M1) and "splits inside one tab stay
  together" (A8) describe a model that no longer exists.** A `TabItem` holds
  one `ContentSnapshot`; splits are between panes (`SplitTree<PaneID>`), each
  pane a tab strip. There is nothing inside a tab to keep. The sizing note
  ("Merge when A has splits: assumed flattened to tabs in B's focused pane")
  governs: A's panes dissolve, every tab survives. The plan's "A with splits"
  test is test 4.
- Plan names the suite `LayoutsTransferTests` and the source
  `LayoutTransfer.swift`; kept both. The test **file** must be
  `LayoutsTransferTests.swift` for bundle routing.
- A28 says "no surface id changes": covered by content-id equality, since a
  surface id is the content id's raw value.

Decisions the plan left open
1. "Pane order" = tree leaf (visual) order, not `panes` array order (2.3).
2. Destination selection, focus and zoom are unchanged by flatten. Reason:
   selecting a tab is a state-side act (may wake a hibernated tab, moves
   zoom); a pure layout op must not imply it. `sourceActiveTabID` is returned
   so M3 can choose to select it.
3. Empty destination (task with all tabs closed) is valid: one fresh pane,
   A's active tab selected. Not "adopt A's tree": D8 says a merge flattens.
4. Extracted layout always gets a fresh pane id; ids injected via
   `makePaneID` (T1 precedent).
5. Identity collision and inconsistent input throw; nothing is repaired.
   Reason: M3 deletes A's record on success, so a silent drop is data loss.
6. Extracting the last tab is allowed at this layer and yields an empty
   remainder; policy (refuse, or delete the emptied shell-only task) is M3's.
7. No equalize and no `LayoutFeature.State` bookkeeping in M1; listed in 2.5
   for M2. Keeps the file free of `@Shared` and testable without dependencies.
8. Locked/ephemeral blocking-script tabs move like any tab; whether a merge
   or detach is refused while one runs is for M2/M3 (flag it in their briefs:
   such a tab has no zmx session to re-home).
9. `Flattened.targetPaneID` is `PaneID?` (nil only when both layouts are
   empty), rather than inventing a pane id that exists nowhere.
10. Plain `throws` with an `Equatable` `Failure`, not typed throws or
    optionals: callers need the reason to log, tests assert the exact case.
